# Мультиагентная разработка 1С

Паттерн: автономный координирующий агент (Hermes/OpenClaw) + специализированные агенты разработки (Cursor/Claude Code/Codex) с shared memory через MCP.

## Аналогия

Как кластер серверов 1С: координатор распределяет, исполнители работают. Агент-координатор = менеджер кластера, агенты разработки = рабочие процессы.

## Архитектура

```
┌──────────────────────────────────────────────────┐
│         Автономный агент (координатор)            │
│         Hermes / OpenClaw                         │
│  ┌─────────────┬──────────────┬────────────────┐  │
│  │ Telegram    │ Память       │ Skills/Rules   │  │
│  │ (мониторинг)│ (Cognee+OV)  │ ( workflow )   │  │

├──────────────────────────────────────────────────┤
│         ACP / CLI connection                      │
├───────────────────┬──────────────────────────────┤
│  Agent: Cursor    │  Agent: Claude Code           │
│  - Правила 1С     │  - Правила 1С                │
│  - MCP (graph+RAG)│  - MCP (graph+RAG)           │

│    инструменты    │    инструменты               │
└───────────────────┴──────────────────────────────┘
```

## Workflow (классический)

### 1. Подготовка
```
📝 Разворачиваем 2 проекта для разработки с ИИ — с правилами
📝 Harness должен быть вменяемым: поддержка ACP, CLI обязателен
📝 Проверяем настройки: MCP включены, индексы проиндексированы
📝 Устанавливаем CLI если нет (cursor cli и т.д.)
```

### 2. Автономный агент
```
📝 Разворачиваем автономного агента: Hermes или OpenClaw
📝 Подключаем: графовый MCP + MCP для работы с данными (обязательно)
📝 Остальные MCP — по желанию
📝 Объясняем где базы, проекты, публикации
📝 Просим поисследовать
```

### 3. Спецификация
```
📝 С ключом /goal даём команду автономному агенту:
   ИСПОЛЬЗУЯ (cursor/claude code/codex + модель)
   НАПИСАТЬ СПЕЦИФИКАЦИЮ для разработки
📝 Спеки лучше прочитать (зависит от критичности)
```

### 4. Разработка
```
📝 С ключом /goal даём команду выполнить разработку
📝 Мониторинг сессий + отчётность каждые N минут/часов
📝 Исправление блокеров
```

### 5. Мониторинг
```
📝 Наблюдаем за прогрессом в Telegram
📝 Корректируем через чат при необходимости
```

## Ключевые принципы

| Принцип | Описание |
|---------|----------|
| **Разделение труда** | Координатор = управление, исполнители = код |
| **Долгосрочные задачи** | Агент-координатор держит long running task очень хорошо |
| **Self-improvement** | Агент создаёт skill/область памяти и улучшает по мере работы |
| **Коррекция через чат** | Прогресс корректируется через Telegram |
| **Специализация** | Исполнители — узкоспециализированные, не общего профиля |
| **Блокеры** | Координатор исправляет блокеры исполнителя |
| **Параллелизм** | Координатор может попросить запустить параллельно |

## Модели

| Роль | Рекомендация |
|------|-------------|
| Координатор (спецификации) | Самое крутое + reasoning (Grok/Terra/Opus) |
| Координатор (разработка) | Зависит от вендора, обычный стек |
| Исполнители | Специализированные модели Cursor/Claude Code/Codex |

## Результат

- ✔️ Long running task любого размера — стабильно
- ✔️ Агент создаёт и улучшает свою память/skills — экономит время и токены
- ✔️ Повторный запуск проще и приятнее
- ✔️ Специализированные агенты для разработки, а не общего профиля
- ✔️ Сложные операции — координатор, массовые — исполнители
