# Архитектура памяти для вайбкодинга

Паттерн: **Cognee** (графовая память) + **OpenViking** (RAG, файловая система) как MCP-серверы для любых AI-агентов.

## Суть

Два дополнительных MCP-сервера дают агенту durable memory, которая переживает переключение моделей, репозиториев и подписок. Контекст экономится — модель находит нужное через поиск, а не держит в контексте.

## Архитектура

```
┌─────────────────────────────────────────────┐
│              AI Agent (любой)               │
│  Hermes / DSH / OpenClaw / Claude Code /... │
├──────────┬──────────┬───────────────────────┤
│  LLM     │  Rules   │  MCP Servers          │
│  model   │  + Skills│  ┌─────────────────┐  │
│          │          │  │ Cognee (graph)   │  │
│          │          │  │ - facts, entities│  │
│          │          │  │ - relations      │  │
│          │          │  │ - semantic search│  │
│          │          │  └─────────────────┘  │
│          │          │  ┌─────────────────┐  │
│          │          │  │ OpenViking (RAG) │  │
│          │          │  │ - files, docs    │  │
│          │          │  │ - rules, skills  │  │
│          │          │  │ - vector search  │  │
│          │          │  │ - FS-like browse │  │
│          │          │  └─────────────────┘  │
└──────────┴──────────┴───────────────────────┘
```

## Workflow

1. **Установить Cognee** (graph memory)
2. **Установить OpenViking** (RAG memory)
3. **Сгрузить факты** — агент выгружает актуальные факты из своей памяти в Cognee
4. **Выгрузить контекст** — агент добавляет правила, скиллы, контекст, доки в OpenViking
   - Для автономных агентов: можно штатную память подменять
   - Для Hermes: память кончается, OpenViking расширяет
5. **Подключить MCP** — оба как MCP-серверы
6. **Работать** — агент ищет через MCP, а не держит в контексте

## Преимущества

- ✅ Без разницы какой агент (Hermes, DSH, OpenClaw, Claude Code...)
- ✅ Без разницы какая модель
- ✅ Параллельно какой репозиторий
- ✅ Переключение между подписками/репозиториями/моделями — незаметное
- ✅ Контекст экономится — модель оперативно находит нужное
- ✅ Для автономных агентов особенно актуально

## Ограничения

- ⚠️ Paperclip — правильнее для согласованной работы агентов. Общая память = систематизация, не оркестрация
- ⚠️ Embedding модель обязательна (для MCP и для всего приличного)
- ⚠️ "Эффект AGI" может захлестнуть
