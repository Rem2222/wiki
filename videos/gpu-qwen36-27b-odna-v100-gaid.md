## Суть в одном абзаце

Пошаговый скринкаст: одна Tesla V100 SXM2 32GB через PCIe-переходник, чистый
Ubuntu 24.04, и на этом стеке гоняется **Qwen3.6-27B-AWQ** — модель на 27
миллиардов параметров помещается в одну карту с контекстом до 129K токенов.
Автор ставит **1Cat-vLLM** (форк vLLM под старые Volta), прогоняет официальный
бенчмарк от разработчиков форка в двух режимах — обычном и **MTP4** — и затем
вешает на всё **Open WebUI** с плагинами. Главный вывод честный: **MTP4 не
универсальное ускорение**, в чате он даёт «плюс-минус погрешность» или даже
замедление, а вот при генерации кода — заметный прирост.

## Пересказ

### Стек и установка

Конфигурация: Tesla V100 SXM2 32 ГБ на PCIe-адаптере, **Ubuntu 24.04 LTS**,
драйвер **580.173.0** (поставился автоматом с галочкой «стороннее ПО»).

Цепочка установки:

1. `apt update` → **Miniconda 3** (отдельное окружение, чтобы не трогать систему)
2. Отключить автозапуск `base`, деактивировать его
3. **CUDA Toolkit 12.8** из официального репозитория Nvidia (ключ, репо, apt)
4. Окружение conda **Python 3.12** → обновить pip/setuptools/wheel
5. **1Cat-vLLM** из готового wheel-пакета — «рекомендуемый способ»
6. Проверка версий: Python, PyTorch, CUDA Triton, 1Cat-vLLM, Flash Attention
   для V100
7. Папка `~/Models` для чекпоинтов

**Токен HuggingFace:** регистрация → Create New Token → тип `read` → имя →
скопировать → в терминале авторизация `huggingface-cli login` → Paste Token →
`Shift+Ctrl+V`. Токен нужен для скачивания модели.

**Структура папок под модель** — не просто `Models/`, а с учётом ревизий:

```
~/Models/Quant-автор/Qwen3.6-27B-AWQ/<номер-ревизии>/
```

Он объясняет: **у одной модели может быть несколько ревизий**, поэтому отдельная
папка под номер. И отмечает: **именно эту версию Qwen3.6-27B-AWQ рекомендуют
разработчики 1Cat-vLLM для запуска на V100**.

### Первый запуск: три окна терминала

Автор сразу ставит рабочую раскладку, которую стоит перенести:

- **Окно 1** — сервер 1Cat-vLLM
- **Окно 2** — `nvidia-smi` с обновлением раз в секунду (нагрузка, VRAM)
- **Окно 3** — чат с моделью

Параметры запуска (первая проверка, без оптимизаций):

| Параметр | Значение | Зачем |
|---|---|---|
| `--attention-backend` | flash-attn для V100 | бэкенд внимания под Volta |
| `--tensor-parallel-size` | 1 | одна карта |
| `--gpu-memory-utilization` | **0.88** | запас на систему, не 100% |
| `--max-model-len` | 32 000 | стартовое окно контекста |
| `--max-num-seqs` | 1 | один запрос за раз |
| `--max-num-batch-tokens` | 8 000 | максимум токенов на шаг |
| `--enable-auto-tool-choice` + `--tool-call-parser` | для Qwen3 Coder | инструменты |
| `--served-model-name` / `--host` / `--port` | имя и адрес API | для клиента |

Результат: модель заняла **почти 27 ГБ видеопамяти** из 32.

### Официальный бенчмарк: 4K → 128K, обычный режим

Скачивает **файл бенчмарка от разработчиков 1Cat-vLLM** (не свой самописный).
Условия: на вход подаётся ровно N токенов (4K/8K/16K/32K/64K/128K), генерация
**до 1 000 токенов**, общий максимум контекста зафиксирован на **129 000**.

| Контекст | Prefill (т/с) | Decode (т/с) |
|---|---:|---:|
| 4K | 1 258.3 | **30.4** |
| 8K | 1 151.9 | 29.9 |
| 16K | *назван как «111,7» в ASR* | 28.3 |
| 32K | *в ASR не разобрано* | 25.9 |
| 64K | 915.1 | 22.3 |
| 128K | 735.6 | **17.2** |

Качество: «тест качества пройден, модель выдала корректный результат».

### Режим MTP4: прирост и цена

**MTP4 (Multi-Token Prediction)** — модель за один шаг предсказывает до четырёх
следующих токенов: меньше последовательных шагов → потенциально быстрее.
Плата — **повышенное потребление памяти**: максимальный контекст пришлось
**снизить с 129 000 до 65 000**.

| Контекст | Prefill с MTP4 | Decode с MTP4 | Прирост decode |
|---|---:|---:|---:|
| 4K | — | 35.3 | **+16.1%** |
| 8K | — | 35.8 | **+19.7%** |
| 16K | — | 35.8 | **+26.5%** |
| 32K | 997.4 | 32.5 | **+25.5%** |
| 64K | 880.1 | 24.1 | **+8.1%** |

Итог по бенчмарку: на обычном режиме 128K контекста → 17 т/с. Прирост от
MTP4 **нарастает к середине и сходит на нет к 64K** (там же и память упёрлась).

### Open WebUI

Отдельное окружение conda **Python 3.11** (изоляция версий) → **Open WebUI
0.11.3** → `localhost:8080`. Плагины:

- **Token Usage Display** — скорость генерации и токены. Там же обязателен шаг:
  **context size override** перезаписать фактическим размером контекста, иначе
  плагин покажет неверное
- **Think Toggle** — включение/выключение режима рассуждения по запросу

Подключение: Add connection → адрес vLLM-сервера → **вход без аутентификации**.
И отключает автогенерацию продолжения чатов («интерфейс, чат, автогенерация
продолжений — выключить»).

Запуск в основном режиме: **--max-model-len 194 000** (без MTP), с MTP4 —
**94 000**.

### Практические тесты в Open WebUI

**Правило холодного старта:** первый запрос после запуска сервера заметно
медленнее (прогрев вычислений и CUDA) — **его в сравнение не включать**.

**Без MTP4:**

| Сценарий | Результат |
|---|---|
| Холодный старт | 27.7 т/с *(не учитывается)* |
| Базовый чат | **43.1 т/с** |
| Рассуждение (Think Toggle) | — |
| Изображение (мультимодальность) | 45.3 т/с |
| PDF, инструкция для чайника | 38.5 т/с |
| Большой контекст ~39K (пересказ четверти «Войны и мира») | **24.5 т/с**, справился за **2 мин** |
| Написать игру | 25 т/с, ~**8 мин** |

**С MTP4:**

| Сценарий | Результат |
|---|---|
| Холодный старт | 23.6 т/с |
| Базовый чат | **40.8 т/с** *(ниже!)* |
| Изображение | **38.7 т/с** *(ниже!)* |
| PDF | 42 т/с *(выше)* |
| Большой контекст ~39K | **26.4 т/с**, справился за **1 мин 10 с** |
| Написать игру | **44.1 т/с**, **3 мин** |

**Average Draft Acceptance Rate** — какой процент предложенных MTP-токенов
основная модель принимает. Шкала автора: до 50% мало, 50–75% нормально,
**75%+ хорошо**. При написании кода показатель высокий.

**Ключевая цифра:** при генерации кода MTP4 дал **+76.4%** (25 → 44.1 т/с,
и 8 мин → 3 мин).

Итоговый вердикт: **«MTP — не универсальная кнопка „ускорить в два раза“»**,
эффективность зависит от задачи; в большинстве задач разница «в пределах
погрешности», а на коде — серьёзный прирост.

Инструкция со всеми командами — в его Telegram-канале (QR в видео).

## Мои выводы

**Ценное:**

- **Имя расшифровано:** ASR пишет «OneCat VLM» — на самом деле это
  **[`1CatAI/1Cat-vLLM`](https://github.com/1CatAI/1Cat-vLLM)**, форк vLLM
  с девизом **«Make Volta Fast Again»**, где V100/SM70 — target первой
  очереди. Репозиторий жив, **превращается в `1Cat-LLM`** (реплейнам уже
  запланирован, добавили поддержку GGUF). Это ключевое для понимания гайда:
  он не про «vLLM вообще», а про конкретный форк
- **Бенчмарк — не его самописный**, а от разработчиков форка, с оговоренными
  условиями (длина входа, лимит генерации, общий контекст). Это сильно выше
  по методологии, чем видео 2
- **Cold-start правило и context size override** в плагине — мелкие, но
  реально экономящие время вещи
- **MTP4 показан честно**: он не только приросты показал, но и два случая
  **замедления** (чат 43.1 → 40.8, изображение 45.3 → 38.7) и **цену**
  (контекст 129K → 65K). Большинство обзоров такие цифры опускает
- **Независимые подтверждения к моему выводу из видео 1:** vLLM действительно
  убил Volta — **vLLM 0.20+ убрал поддержку sm_70** (минимум CUDA 13.0.2,
  PyTorch 2.11, сборки без sm_70, ошибка «no kernel image is available» /
  «Minimum capability: 75»). Источники: nizamov.school, nextgen-pc.online.
  То есть «танцы с бубнами» из первого видео — не пугалка, а факт

**Где слабо:**

- **Все практические тесты — по одному прогону, без повторов.** Ни разницы
  выборки, ни погрешности. Он сам пишет «плюс-минус в пределах погрешности»,
  но **погрешность не измерял** — сравнивает одиночные прогоны
- **Расхождение в его же данных:** по 39K-контексту 2 мин против 1 мин 10 с
  — это **в 1.7 раза**, что никак не «в пределах погрешности». Либо ответы
  отличались по длине (он не говорит), либо на длинном контексте MTP реально
  помогает сильно. Свои же итоговые формулировки это не объясняет
- **«+76.4% на коде» — на одном запросе** (написать игру), один раз, и при
  этом сгенерированные игры **разные** («выглядит немного по-другому») —
  значит, объём текста ответа тоже отличается. Это не бенчмарк, а кейс
- **«27B» в заголовке против «двадцатимиллиардной модели» в тексте** — сам
  себе противоречит (27 ≠ 20)
- **Нет ни одного сравнения с конкурирующим железом**: только V100. Ни 3090,
  ни 4060 Ti, ни 5060. Про «работает локально без подписок» — верно, но
  выигрыш против аренды/подписки не посчитан
- **Привязка к конкретной модели:** рекомендованный чекпоинт AWQ — «тот, что
  рекомендуют разработчики форка». Для другой модели 27B или другого
  квантования результаты могут и не перенестись, он это не проверяет
- **Коммерческий хвост:** вся инструкция — в его Telegram (закрытый канал
  с QR), не в описании видео

**Что это даёт нам:** V100 32GB с контекстом 129K и 27B моделью — это
**не для нашего VPS** (11 ГБ RAM, без GPU), но как **справочник конфигурации**
ценно: параметры запуска, структура папок, шкала acceptance rate, правило
холодного старста. И как ориентир, если брать карту под XE2690 (64 ГБ RAM
подошли бы для offload'а).
