## Что это

Subquadratic — исследовательская компания, которая строит long-context модели на своём методе **SSA (Subquadratic Sparse Attention)**: линейное внимание, при котором стоимость каждого токена остаётся постоянной при росте контекста. Это первая «полностью субквадратичная» LLM.

Продукт — **SubQ Snap**, и это не генератор текста. Это decision-модель («System One»): на вход получает состояние (текст, структура, до 4 изображений), на выход отдаёт типизированные ответы с вероятностями. Веса закрыты, только hosted API.

Вход: `POST https://api.subq.ai/v1/systemone`, `Authorization: Bearer <ключ>`.

Три типа вопросов в одном запросе:

- `noul` — «да/нет» с вероятностью (0..1)
- `choice` — вероятность по каждому варианту плюс `confidence`; критерий `null` = «ничего из этого»
- `score` — вероятность по каждому уровню плюс взвешенный `score` и `legend`

Версии: Snap 12.10.2026 → Snap 1.1 22.10.2026 → Snap 1.2 11.11.2026. Модели `subq-snap-1.1` и `subq-snap-preview` отключены, запросы к ним маршрутизируются на 1.2.

## Цены и лимиты

- Вход **$0.04 за 1M токенов**, **выход бесплатный** (в ответе `usage.output_tokens: 0`)
- Контекст 384k токенов (AA указывает 393k), текст и изображения
- «Free 100M tokens for new users» — заявлено на сайте
- Остаток и расход **по API не видны**: `/v1/usage`, `/v1/credits`, `/v1/subscription`, `/v1/limits`, `/v2/quotas` и прочие — все 404. Баланс только в консоли `console.subq.ai/billing`
- Вендорская цифра: 100k-токенный запрос — около секунды

## Вторая модель: SubQ Savant 1.4

Long-context модель для генерации текста, **early access** — включается по организации, пока не включено, любой запрос отдаёт `403 model_not_allowed`.

- Контекст **4M токенов** в одном запросе
- Цены: вход $0.10/Mtok, кэшированный вход $0.01/Mtok, выход $0.50/Mtok; тариф одинаков при любой длине промпта
- Всегда рассуждает: `reasoning_effort` `low`/`high`/`max`, `none` → 400; `temperature` фиксирована в 1, любое другое значение → 400
- Reasoning тарифицируется как выход
- Пример вендора: прочитать 1M токенов контрактов и выдать 2000 токенов ответа (с reasoning) — около $0.10
- OpenAI-совместимые `/v1/chat/completions` и `/v1/responses`

## Живой замер (14.11.2026, ключ из `.env`)

Decisions API, три прогона одного запроса (state про пациента с астмой, три вопроса: noul / choice из 4 / score из 3):

- HTTP 200, латентность **370 / 398 / 421 мс, медиана 398 мс** (у Artificial Analysis 162 мс — считают у себя и, видимо, в США)
- `usage`: input 225 токенов, output 0 → стоимость запроса ≈ **$0.000009**
- Ответы **побайтово идентичны во всех трёх прогонах** (`noul: 0.9951890707015991`) — sampling отсутствует, модель детерминирована
- Качество ответа осмысленное: `escalate 0.995` (одышка при астме), `choice nurse_line 0.973` при `confidence 0.964`, `score 1.39` между «в течение суток» и «в течение часа» при **confidence 0.394** — то есть модель честно сообщает, что в третьем вопросе уверена слабо
- `POST /v1/chat/completions` с `subq-snap-1.2` → **400** «does not support completions requests»
- `POST /v1/chat/completions` с `subq-savant-1.4` → **403 model_not_allowed** (early access не включён)

## Независимая оценка: Artificial Analysis Decision Index

Страница AA по Snap 1.2 (14.11.2026):

- **Decision Index 73**, #2 из 22 (медиана 66), 4 из 4 «unit»
- **162 мс** на задачу, #8 из 22 (медиана 209 мс)
- **$137 за 1M задач** на индексе, #11 из 22 (медиана $137)
- Snap 1.1 — 68 баллов, Snap 1.2 — 73 (+5). AA 14.11.2026: 1.2 вничью с **Drex Max v1.1 (73)** и **GLiDE v1.2 (73)**, разница в пределах 0.1
- Крупнейшие приросты 1.2: AA-Paperclip **+8** (all-pass 46% → 62%) и AA-Symmetry **+8** (устойчивость к перестановке вариантов)
- Важная оговорка от AA: прирост на AA-Omniscience-Decision и HLE-MultiChoice получен **за счёт отказов отвечать, а не точности** — non-hallucination 85% → 89% и 46% → 55%, при этом точность не изменилась (21% и 9%), доля попыток на Omniscience упала с 33% до 29%
- По неокруглённым числам AA (проверка 12.11.2026) Snap 1.2 = 72.6, второй из 19 моделей, Drex Max v1.1 чуть впереди

## Чем отличается от обычного провайдера LLM

Три релевантных для нас сценария:

1. **Маршрутизация** — выбор файла, инструмента, скилла внутри агента. Большинство шагов агента это простые решения («какой инструмент», «нужен ли этот файл»), и $0.04/Mtok против $0.60–$2.00 у чатов — на порядки дешевле при 384k контекста.
2. **Триаж входящего** — `choice` с вероятностями хорошо ложится на «кому/в какую очередь»: почта, SmithsChat, мониторы. `confidence` даёт готовый порог для эскалации человеку.
3. **Фильтр «материально ли событие»** — `noul` на входах вотчдогов (freshauto, competitor-news-monitor) вместо дешёвого чата. Решение принимается без генерации текста, в разы быстрее.

Ограничение: текста SubQ Snap не пишет вообще. Как основной провайдер в Hermes не встаёт — только как отдельный шаг «оцени вот это» перед чатом. Подключение = свой HTTP-вызов в скрипте, не OpenAI-совместимый провайдер в `config.yaml`.

## Вывод

- **Это самое необычное из присланных: не «ещё один чат», а decision-модель.** Вероятности + `confidence` + детерминизм + 384k контекста за $0.04/Mtok.
- В интерактивный чат не берём (текста не генерит). Куда реально может лечь — фильтры и маршрутизация в существующих скриптах: вотчдоги, триаж почты/SmithsChat, выбор скилла.
- **Savant 1.4 интереснее по цифрам** (4M токенов за $0.10/Mtok) — но early access, нужна заявка на `subq.ai/small#waitlist`, и организациям выдают вручную.
- Отзывов пользователей на момент разбора нет: сервис младше месяца, публичных обсуждений (HN/Reddit) не нашлось, вся внешняя оценка — Artificial Analysis и собственные бенчмарки вендора (LongDecisionBench, 9 открытых long-context бенчмарков).
- Ключ прислан открытым текстом в чат → после тестов перевыпустить.
