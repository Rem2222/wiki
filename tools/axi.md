# AXI — Agent eXperience Interface

**Кто:** Kun Chen (`kunchenguid`) — разбор его профиля в `[[tech/kun-chen-tdd-eval]]`.
**Статус:** записано для дела, **не устанавливалось**. Нужен отдельный старт от Романа.

## Суть в двух абзацах

Сейчас агенты ходят во внешние сервисы двумя путями: **CLI, написанные под
человека**, и **MCP** (структурированный протокол инструментов). Оба накладывают
издержки — человекоцентричный CLI отвечает длинным help'ом и интерактивными
промптами, MCP — многократными round-trips и толстыми схемами.

**AXI — новая парадигма: агентоцентричные CLI**, спроектированные по 10
принципам, где **токен-бюджет считается ограничением первого класса**
(«first-class constraint»), а не побочным эффектом.

## 10 принципов

Таблица сгенерирована из `principles.yaml`, полная спецификация каждого — в
`.agents/skills/axi/SKILL.md`:

| # | Принцип | Суть |
|---|---|---|
| 1 | **Token-efficient output** | Формат [TOON](https://toonformat.dev/) вместо JSON — экономия ~40% токенов |
| 2 | **Minimal default schemas** | 3–4 поля на элемент списка, не 10+ |
| 3 | **Content truncation** | Обрезка большого текста с подсказками размера и escape-хатчем `--full` |
| 4 | **Pre-computed aggregates** | Счётчики и статусы считаются заранее, чтобы не делать лишних запросов |
| 5 | **Definitive empty states** | Явное «0 результатов» вместо неоднозначного пустого вывода |
| 6 | **Structured errors & exit codes** | Идемпотентные мутации, структурированные ошибки, без интерактивных промптов, fail loud на неизвестных флагах |
| 7 | **Ambient context** | Сначала opt-in интеграции сессии, потом on-demand скилл |
| 8 | **Content first** | Без аргументов — живые данные, а не help-текст |
| 9 | **Contextual disclosure** | После каждого вывода — подсказка следующего шага |
| 10 | **Consistent way to get help** | Краткий справочный текст на подкоманду, когда агенту нужна помощь |

Что тут ценного для нас: принципы 3, 4, 5, 8 — это ровно то, что снижает
раздутые ответы в нашей работе (многострочные help'ы, повторные запросы за
тем же счётчиком, пустые выводы, по которым непонятно, «ничего нет» или
«ошибка молчала»).

## Результаты — это его сильная сторона

Он продаёт **цифрами, а не мнениями**. Оба бенчмарка — на Claude Sonnet 4.6,
публикуется методика (условия × повторы):

**GitHub-операции** — 425 прогонов (17 задач × 5 условий × 5 повторов):

| Условие | Успех | Стоимость | Длит. | Ходы |
|---|---:|---:|---:|---:|
| **`gh-axi`** | **100%** | **$0.050** | 15.7s | **3** |
| `gh` (CLI) | 86% | $0.054 | 17.4s | 3 |
| GitHub MCP | 87% | $0.148 | 34.2s | 6 |
| GitHub MCP + ToolSearch | 82% | $0.147 | 41.1s | 8 |
| MCP + Code Mode | 84% | $0.101 | 43.4s | 7 |

**Браузер** — 490 прогонов (14 задач × 7 условий × 5 повторов):

| Условие | Успех | Стоимость | Длит. | Ходы |
|---|---:|---:|---:|---:|
| **`chrome-devtools-axi`** | **100%** | **$0.074** | 21.5s | **4.5** |
| `dev-browser` | 99% | $0.078 | 28.6s | 4.9 |
| `agent-browser` | 99% | $0.088 | 24.6s | 4.8 |
| `chrome-devtools-mcp-compressed` | 100% | $0.091 | 29.7s | 7.6 |
| `chrome-devtools-mcp-search` | 99% | $0.096 | 29.4s | 7.5 |
| `chrome-devtools-mcp` | 99% | $0.101 | 26.0s | 6.2 |
| `chrome-devtools-mcp-code` | 100% | $0.120 | 36.2s | 6.4 |

**Вывод из его же данных:** аккуратный AXI-CLI обходится **в 3 раза дешевле
MCP** при том же результате (GitHub: $0.050 против $0.148) и делает это за 3
хода вместо 6. По браузеру разница меньше: $0.074 против $0.096–0.120, но
ходы — 4.5 против 6.2–7.6.

**Честные оговорки к его цифрам:**

- модель одна (Sonnet 4.6) — автор прямо пишет: «results for other models are
  simply not published here, and they may respond differently to output format»
- свои инструменты против стороннего MCP — конфликт интереса не устранён,
  методика опубликована, но независимого прогона нет
- проценты успеха различаются на единицы случаев — на 17 задачах разница 86%
  против 100% это ~2–3 задачи
- результаты других моделей могут отличаться, сам он это признаёт

## Каталог

**Официальные:**

- **`gh-axi`** (324⭐, TypeScript, MIT) — GitHub: issues, PRs, workflow runs,
  releases. Обёртка над официальным `gh` с агентоцентричным выводом
- **`chrome-devtools-axi`** (413⭐, TypeScript, MIT) — браузер: навигация, клики,
  заполнение, извлечение с объединёнными операциями и query-фильтрацией.
  Обёртка над `chrome-devtools-mcp`
- **`lavish-axi`** (4 030⭐) — превращает HTML-артефакты агента в поверхность
  совместного ревью: аннотации, комментарии, обратная связь агенту
- **`quota-axi`** — репорт по локальным квотам Claude, Codex, Cursor, Copilot,
  Grok для routing-aware агентов; data-only, local-first

**Сообщество** (к моменту разбора): `jj-axi` (Jujutsu VCS), `npm-axi` (реестр
npm), плюс другие по `catalog.yaml`.

Установка (согласно README):

```sh
npm install -g gh-axi
npm install -g chrome-devtools-axi
```

И строка в `CLAUDE.md` / `AGENTS.md`: «Use `gh-axi` for GitHub and
`chrome-devtools-axi` for browser automation.»

## Соответствие нашему VPS

- Node **v22.23.2**, npm **10.9.8** — установка `npm install -g` возможна
- `gh` CLI **уже установлен** (`/usr/bin/gh`) — `gh-axi` кладётся поверх
  существующего инструмента
- **Не установлено у нас:** ни одного AXI, TOON в конфиге нет
- `chrome-devtools-axi` для нас менее приоритетен — у нас есть Playwright 1.63
  с Chromium (см. `[[tech/freshauto]]`), а бенчмарк AXI против
  `chrome-devtools-mcp` — против другого MCP, не против Playwright

**Потенциальная польза для нас:** `gh-axi` поверх уже установленного `gh` —
самый дешёвый вхождение (одна npm-команда, ничего не ломает). Выгода в 3 раза
по цене против MCP касается MCP-пути, у нас же `gh` уже работает напрямую, так
что прирост будет в экономии ходов и токенов, а не в кратности.

## Что связано

`no-mistakes` того же автора — git-прокси с валидационным пайплайном:
`[[tools/no-mistakes]]`. Внутри `no-mistakes` есть `no-mistakes axi` —
non-interactive TOON-интерфейс к тому же approval-флоу, то есть экосистема
замыкается.

## Решение

**Не устанавливалось.** Зафиксировано для дела — по правилу Романа: новые
внешние инструменты сначала в вики, не ставить. Кандидат на установку —
`gh-axi` (npm-команда, `gh` уже есть), но только по отдельной команде.
