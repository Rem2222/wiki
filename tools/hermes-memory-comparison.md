# Сравнение систем памяти для Hermes

Оценка по 6 болям из ТЗ (20.08.2026). HTML-версия с полными таблицами:
[[tools/hermes-memory-comparison.html]] (или `https://rem2222.top/hermes-memory.html`).

## 6 болей (критерии)

1. **Стабильность** — не падает, durable (локальный диск цел при падении процесса; Node-движок слабее Go/SQLite)
2. **Разгрузка MD** — автовынос из оперативной MEMORY/USER в долгосрок
3. **Единая точка правды** — вместо 3 несвязанных систем
4. **Многослойность** — факты/паттерны/уроки/логи раздельно
5. **Авто-retrieve** — сам ищет память перед turn («посмотри в памяти» без напоминаний)
6. **Сквозная память** — общий доступ для неск. агентов (VPS+Windows)

## Выводы

- **Боли 1 (стабильность) и 3 (единая точка)** решаются любым из: Hindsight, Supermemory, Holographic, Mem0, ClawMem, Honcho — все стабильнее текущего agentmemory.
- **Боли 4 (многослойность) и 6 (сквозная)** закрывают почти все кандидаты (граф/типы/проф + multi) — больших различий нет.
- **Классического «закрывает всё сам» нет ни у кого.** Пункты 2 и 5 (разгрузка MD и авто-retrieve) — это не про хранилище, а про то, как агент пишет/ищет (hooks/injection). Любая система даёт их только при правильной настройке.
- **Платные** (TencentDB -61% токенов, RetainDB $20/мес) — ради токенов при текущих объёмах не нужны.

## Рекомендация

- **«Починить стабильность сейчас»** → **Holographic** (встроен, SQLite, 0 зависимостей, max-стабильность — антипод падающего agentmemory).
- **«Закрыть максимум болей»** → **Hindsight** (локальный Postgres + граф + auto_recall/retain + reflect-синтез) или **ClawMem** (нативный Hermes, без облака, hybrid RAG).
