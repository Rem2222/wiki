# Aura Autopilot: открытый агент-плейтестер для Unreal, Unity и Godot

## Что это

**Aura Autopilot** (`ramenvr/autopilot`, слоган репозитория — «Play any game») — открытый автономный агент-плейтестер: играет в вашу игру в реальном времени, ищет баги, проверяет утверждения и достигает поставленных игровых целей. Разработчики — команда Aura (`tryaura.dev`), у них же коммерческая подписка и агент для Unreal/Unity.

Ключевая идея, которой они сами себя продают: агент учится на своих прогонах, поэтому «видимо умнеет» — с каждым запуском быстрее проходит задачу и играет разумнее (раньше уклоняется, лучше выбирает оружие, точнее целится).

## Как работает

Промпт бывает четырёх типов:

- **Exploration** — «изучи систему крафта в Lvl_Main»
- **Testing** — «пройди открытый уровень и скажи, что выглядит неправильно»
- **Verification** — «проверь, что дерево трясётся от удара топором»
- **Goal** — «убей босса, держа здоровье выше 20 %»

Дальше по кругу: `Autopilot` открывает окно PIE, читает исходный код проекта, изучает запущенную игру и начинает играть. Технически это двухслойная схема: **LLM-агент** (по умолчанию OpenCode, есть варианты Claude Code и Codex) пишет «харнесс» — код обвязки под конкретную игру, а **decision model** во время игры отдаёт конкретные решения (какое действие выполнить). Харнесс переписывается по мере того, как агент узнаёт игру. В конце PIE закрывается сам, а на выходе — отчёт о найденных проблемах и запись прогона (H.264 MP4, модуль `media.py`; описание кадров через vision-модель Anthropic — напрямую, через релей Aura или через OpenCode Zen).

## Память — это папка, а не векторная база

Интересное инженерное решение: память проекта — обычный каталог `memory/<project>/`

- `notes.md` — факты, проверенные прошлыми прогонами: управление, механики, подводные камни
- `lib.py` — код харнессов, который оказался переиспользуемым
- `runs/<id>/` — версии харнессов, трассы и отчёт каждого прогона
- `codex/` — текстовая копия кода игры (пересобирается, памятью не считается)
- `.codex-seen.json.gz` — хэши файлов, с которыми работал прошлый прогон, чтобы следующий знал, что изменилось

Сброс памяти («Reset memory») файлы не удаляет, а откладывает в сторону. То есть «опыт предыдущих запусков» здесь — не эмбеддинги, а заметки и код, которые агент читает на старте.

## Два способа запустить

1. **Плагин в движке + аккаунт Aura** — распаковать сборку в `Plugins/` (Unreal), поставить тарбол через Package Manager (Unity) или положить в `addons/` (Godot), залогиниться, пройти онбординг. Первый прогон можно сделать 10-минутным исследовательским, чтобы наполнить память проекта
2. **Через MCP из кодинг-агента** — `autopilot connect claude` или `autopilot connect codex`, дальше в Claude Code или Codex писать «Use Autopilot to…». В этом режиме ваши токены LLM идут по вашей подписке Claude/ChatGPT, а Aura считает только обращения к decision model

Есть и вариант **BYOK** — свой ключ TypeSafe (`console.typesafe.ai/keys`) вместо аккаунта Aura. То есть «полностью свободного и локального» режима нет: decision model — их сервис, и он либо по подписке Aura, либо по своему ключу TypeSafe. Открытый код — это агентская часть и MCP, а не модель решений.

Технические требования из `pyproject.toml`: Python **≥ 3.12**, зависимости `typesafe-sdk`, `requests`, `python-dotenv`, `websockets`, `av` (кодирование записи), `anthropic`; агент OpenCode работает под **Bun**, опционально `claude-agent-sdk` или `openai-codex` (~150 МБ).

## Бенчмарк: что заявлено и что на самом деле

В официальном бенчмарке с сайта: одна игра на Unreal Engine 5.8, семь задач, каждый прогон стартует с пустой памятью, «читерский» прогон считается провалом.

- **Скорость (среднее на задачу):** Autopilot **262 с**, Claude Code **437 с**, другой игровой агент **508 с** → заявлено **1.7× быстрее Claude Code** и **1.9× быстрее другого агента**
- **Точность:** Autopilot **7 из 7**, Claude Code **5 из 7**, другой агент **4 из 7** — задачи, пройденные с первой попытки

⚠️ **Поправка к пересказу, который ходит по каналам.** В анонсе (Ai Journal) написано «преимущество в точности 28,7 % перед Claude Code и трёхкратное ускорение». Ни в репозитории, ни на сайте таких чисел нет: поиск по коду по `28.7` даёт ноль совпадений, а на сайте стоят 1.7× и 1.9×, не 3×. Реальная разница в точности — две задачи из семи (7/7 против 5/7), что в проценты переводится по-разному в зависимости от базы. Числа из анонса считать неподтверждёнными.

Ещё из их заявлений: агент играл в шутеры от первого лица, souls-like, мобильные match-3, пошаговые JRPG, survival-крафт и RTS.

## Что внутри репозитория

- `autopilot/agents/` — рантаймы агентов: `claude_code.py`, `codex.py`, `codex_tools.py`, `opencode.py` (+ `opencode_host/` на Bun), `external.py`, `session.py`, `toolserver.py`
- `autopilot/kit/harness.py` — генерация харнессов, `autopilot/memory.py` и `aura_memory.py` — та самая память, `autopilot/codex.py` — текстовая копия кода игры
- `autopilot/mcp.py` — MCP-сервер, `plugin/` — плагины движков, `packaging/` — упаковка сборок, `tools/` — сборка, `bench/` — прогон бенчмарка (`run_autopilot.py` + `example.json`)
- `autopilot/assistants/SKILL.md` — скилл для ассистентов, `KIT.md`, `engines/unity.md`, `engines/godot.md`
- CI на GitHub Actions: `ci.yml`, `commit-lint.yml`, `download.yml`, `uninstall-e2e.yml`, `aura-sync.yml`

## Стоит ли пробовать

Плюсы: открытый код (агент и MCP), работа с вашими подписками Claude/Codex, четыре типа промптов вместо одного «поиграй», память в виде читаемых файлов, есть бенчмарк-скрипт и пример набора задач.

Ограничения, которые надо взвесить: проекту чуть больше недели, версия 1.0.0 с несколькими пересборками; decision model — облачный сервис, «просто локально» не выйдет; Linux не поддерживается; для UE нужны десятки гигабайт движка и нормальная видеокарта (на GT 1030 в домашней машине UE-путь будет мучением, Godot 4.7 — самый лёгкий вариант для пробы); бенчмарк — одна игра и семь задач, обобщать на свой проект рано.
