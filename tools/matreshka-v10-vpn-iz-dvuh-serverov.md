# Матрёшка v1.0 — VPN из двух серверов

## Что это

**«Матрёшка» v1.0** — готовый рецепт VPN из двух арендованных серверов: вход в РФ, выход за границей, плюс автоматическая настройка роутера Keenetic/Netcraze и отдельной Wi‑Fi сети `Matryoshka`. Пришёл архивом `Матрёшка_v1.0.zip` от @cgevent вместе с рекламным постом и реферальными ссылками на хостеров.

Архив распакован **только для чтения**, ничего не запускалось. SHA256 исходника: `55130bf23bf7a935b9188aa77815059dc42e787189469d02ffb0152d5535137d`. Оригинал скопирован в `raw/matryoshka-v1-0.zip`.

Состав (7 файлов):
- `ПРОЧТИ_АГЕНТ.md` — пошаговый рецепт для ИИ-агента;
- `ПРОЧТИ_ЧЕЛОВЕК.txt` — короткая инструкция владельцу;
- `МОИ_СЕРВЕРЫ.txt` — шаблон с адресами/паролями, **в архиве только заглушки**, реальных ключей нет;
- `scripts/matryoshka.sh` — базовая настройка серверов: AmneziaWG, nftables, sysctl, списки российских сетей, стоп-кран;
- `scripts/matr_ssh.py` — SSH по paramiko, загрузка скрипта на оба сервера, получение конфигов;
- `scripts/keenetic.py` — настройка роутера через его локальный RCI API;
- `scripts/matr_cfg.py` — чтение конфига и маскировка паролей в выводе.

## Как устроено

```text
телефон / ТВ / комп → Keenetic → ВХОД (сервер в РФ) → ВЫХОД (сервер за границей) → интернет
                                      └→ российские сайты (ВК, банки) идут напрямую с входа
```

- Провайдер дома видит только российский вход; выход открыт только для входа.
- Российские сайты видят адрес входа, остальной мир — один и тот же «липкий» адрес выхода.
- Разделение по списку российских сетей: он скачивается с `ipdeny.com`, резерв — RIPEstat.
- Протокол AmneziaWG (WireGuard с маскировкой), на связке вход↔выход добавляется I1.
- IPv6 на серверах выключается; стоп-кран — политика роутера «только туннель».

## Утверждение из поста → реальность

| Утверждение | Проверка по файлам |
|---|---|
| «ВК стучит, доказательств нет» | Честно: в архиве нет никаких доказательств слежки ВК. Схема не зависит от этой гипотезы и работает как обычный split-tunnel. |
| «ВК, банки, Авито видят российский адрес» | Реализовано через список российских подсетей. В самой инструкции прямо сказано: если список не загрузится, `2ip.ru` покажет заграницу; лечение — `ru-update`. |
| «YouTube, Claude, Gemini видят один заграничный IP» | Да, это адрес выхода; проверка `ipinfo.io` и повтор через час описаны в шаге 4. |
| «Упал туннель — интернета нет» | Стоп-кран есть: отдельная политика Keenetic и проверка `down`/`up`. Но это надо проверять-living на конкретной модели роутера. |
| «Wi‑Fi Matryoshka появится сама» | Только если модель поддерживает создание Wi‑Fi через API; инструкция признаёт, что на части моделей нужно сделать это вручную в веб-интерфейсе. |
| «Debian 13, нужен IPv4» | Верно: скрипты поддерживают Debian 11/12/13 и Ubuntu 22/24, проверяют наличие IPv4; Debian 11 сами переводят на архивные репозитории. |
| «Агент сам настроит всё» | Скрипты действительно правят оба сервера рутом и роутер через API, но требуют заполненного `МОИ_СЕРВЕРЫ.txt` и установленного `paramiko`. Это внешние действия с реальными серверами — в читаемом архиве их нет. |

## Что я проверил в скриптах

- Внешние адреса, куда обращаются скрипты: `api.ipify.org`, `ifconfig.me`, `go.dev`, `dl.google.com`, `github.com/amnezia-vpn/*`, `ipdeny.com`, `stat.ripe.net`, плюс адрес роутера из конфига. **Вызова к домену автора или стороннему телеметрическому серверу не нашёл.**
- `matr_cfg.py` собирает все значения с «ПАРОЛЬ» в ключе и заменяет их на `<скрыто>` в выводе; `keenetic.py` дополнительно маскирует приватные ключи WireGuard.
- `eval` в `matryoshka.sh` используется только для присваивания случайных чисел `H1..H4` — пользовательские строки туда не попадают.
- SSH идёт через paramiko; для не-root пользователя команда оборачивается в `sudo -S` с паролем на stdin. Пароль в лог не пишется.
- `keenetic.py` обещает не трогать существующие подключения, а только добавлять новые; перед этим делает резервную копию настроек.
- **Не проверял:** реальную работу на живых серверах, совместимость с конкретной прошивкой Keenetic, отсутствие багов в nftables-правилах. Архив не запускался.

## Чем интересно Роману

У нас уже есть [[ops/services/tailscale]] с домашним exit node, [[tech/amneziawg-keenetic]] и заметки про WARP/Netbird. «Матрёшка» — не замена им, а другой сценарий: **один и тот же роутер отдаёт российским сайтам российский IP, а зарубежным — стабильный зарубежный**, с полным стоп-краном.

- Сейчас: жене нужно зайти в ВК/банк, а YouTube и ИИ-сервисы должны видеть зарубежный IP → станет: отдельная Wi‑Fi `Matryoshka`, где splitting делается на входе, а не в браузере.
- Сейчас: Tailscale exit node — это один туннель на всё → станет: два сервера и разделение по географии, «липкий» выход.
- Сейчас: настройка AmneziaWG на Keenetic делается руками ([[tech/amneziawg-keenetic]]) → станет: скрипт сам создаёт подключение, политику и Wi‑Fi, при этом существующие настройки обещает не трогать.

**Чего НЕ делает:** не анонимизирует полностью (свой сервер в базах — «хостинг», вход видит адреса назначения, HTTPS-содержимое — нет), не обходит блокировки вход↔выход насовсем (обратная связь VLESS/Reality обещана в следующей версии), не маскирует аккаунт/часы/язык, не работает без двух серверов с IPv4. Российский вход подчиняется российским законам — это честно написано в инструкции.

Ограничения и риски: для работы нужны root-пароли двух серверов и пароль администратора роутера; скрипты меняют sysctl, nftables и конфигурацию роутера. Реферальные ссылки в посте — способ автора заработать, к технической схеме отношения не имеют.
