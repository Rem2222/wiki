## Что за сервис

Релей к моделям по OpenAI-совместимому протоколу: `https://api.apmix.ai/v1`, ключ формата `apx_live_…`, один ключ на OpenAI- и Anthropic-формат, тарификация weighted-токенами. Тарифы Starter / Pro / Max, free-план — 4 млн токенов без карты.

Домен `apmix.ai` зарегистрирован **09.09.2026**, оператор Nomvel, платежи через Fungies/Creem — то есть сервису на момент замера два месяца.

## Что показала авторизация (важно для повторения)

Регистрация автоматизации недоступна. `/login` отдаёт **Vercel Security Checkpoint**, затем форма с **Cloudflare Turnstile** («Verify you are human»); кнопка submit навсегда остаётся в состоянии `Checking your browser…`. Не проходится ни headless-Chromium (60 с), ни headful под Xvfb с кликом по iframe — виноват датацентровый IP. Ключ заводится **только вручную в браузере человеком**, ввод email + magic link; аккаунт создаётся при первом входе.

## Квота и лимиты (живые данные, `/v1/usage`)

- allowance: **4 000 000** токенов, used после всех замеров **2 289** (0.057%), remaining 3 997 711
- `resets_at: null`, `limits: {daily: null, weekly: null}` — то есть дневных и недельных капов нет, расход идёт из общего пула
- доступно **2 модели**: `deepseek-v4.1-flash-1017-free`, `nemotron-3.5-super-vl-free`
- ключ `Hermes_vps`, `usage_limit: null`
- `/v1/limits`, `/v1/quota`, `/v1/me`, `/v1/key` → **404**; расход смотреть только в `/v1/usage`
- заголовков `x-ratelimit-*` / `retry-after` нет ни в одном ответе

## Замеры скорости

Методика: один и тот же промпт (написать функцию `group_csv` на Python), `max_tokens 2500`, streaming, три прогона на каждую цель, те же секунды по МСК.

| | APMIX free (`deepseek-v4.1-flash-1017-free`) | наш qwen-tp (`deepseek-v4.1-flash-1017`) |
|---|---|---|
| TTFT (первый токен) | 14.1 / 27.3 / 39.4 с — **медиана 27.3 с** | 0.82 / 0.84 / 0.89 с — **медиана 0.84 с** |
| Всё время до конца | 14.7 / 28.3 / 39.8 с — медиана 28.3 с | 8.2 / 9.4 / 15.1 с — медиана 9.4 с |
| Выдано токенов | 122 / 147 / 170 | 1350 / 1555 / 2321 (в основном reasoning) |
| Reasoning | нет (`reason_sym 0`) — отвечает сразу, но ждать всё равно | есть, первый токен 0.84 с, текст с 8.9 с |

Качество при этом нормальное: `finish_reason: stop`, код на Python дописан целиком, синтаксис правильный, BOM и отсутствующая колонка обработаны. Проблема не в ответе, а в ожидании.

## Поведение под нагрузкой

8 одновременных запросов с `max_tokens 16` («ответь одним словом»):

- ответы: 16.2, 44.2, 72.1, 74.2, 85.3, 113.3 с
- **2 из 8 — таймаут по 120 с**, ответа не было
- коды 429 не выдаёт вообще: вместо отказа копит запросы в очередь

Для сравнения: наша цель отвечает на такой запрос за 0.8–1.2 с.

## Независимые пробы качества релея (собрано 14.11.2026)

- BazaarLink (74 прогона за 22 дня): **6 из последних 24 проб — подмена модели** (25%); под видом kimi-k3.1-pro и gemini-4-carbon отдавали DeepSeek V4.1 Flash. Наша модель — match на пробе 14.11 13:29
- Veridrop (6 проверок): медиана 71/100, OpenAI-протокол 93/100, Claude 70/100, `thinking_signature` 0%, **`token_billing` 0 из 2** (учёт токенов не сходится), `pdf` 0%

## Вывод

**Резерв для фоновых задач, не основной канал.** 4 млн токенов без дневного лимита — это дешёвый запас на ночные прогоны, разборы, суммаризацию, где 30 секунд ожидания не мешают. В интерактив (чат, виджеты, ответы Роману) не годится: медиана TTFT 27 с против 0.84 с у qwen-tp, а под параллельной нагрузкой очередь больше двух минут.

Держим ключ в `/root/.hermes/.env` как `APMIX_KEY`, расход проверяем через `/v1/usage`. Ничего в конфиг Hermes не прописываем — только ручные вызовы, когда основной канал занят.
