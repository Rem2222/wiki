# Elephant-Goldfish Model: слон держит контекст, золотая рыбка ревьюит без него

## Что это

**EGM** (`google/elephant-goldfish-model`) — открытый плагин для ИИ-агентов, которые пишут код. Девиз: «Design with an elephant. Review with a goldfish» — проектируй с памятью слона, проверяй с памятью золотой рыбки.

Логика простая и оттого убедительная. Агент с длинным контекстом помнит требования, прошлые решения, тот чат со вторника и дизайн авторизации. И именно поэтому перестаёт замечать, что́ он **предполагает**: всё выглядит согласованным, потому что согласовано само с собой. EGM разделяет работу:

- **Слон** держит полный контекст проекта и пишет черновик спецификации.
- **Золотые рыбки** — ревьюеры в свежих субагентах, без истории разговора. Они читают только черновик и его источники и находят невысказанные допущения, неясные требования и риски реализации.
- **Человек** решает компромиссы и утверждает спеку до того, как начнётся код.

Три шага по кругу: brainstorm идеи → draft спеки по секциям → review свежими глазами → resolve находок → повтор, пока дизайн держится.

Проект от Google, но в README прямо: «This is not an officially supported Google product». Лицензия Apache-2.0.

## Цифры на 09.11.2026

Проверено через GitHub API, не по пересказу:

- 16 133 звезды, 1 179 форков, 77 открытых issues
- язык Python, размер репозитория ~11,9 МБ
- создан 13.09.2026, последний пуш 09.11.2026 — проект живой, правки идут ежедневно
- релизы: `v0.1.0` (27.10.2026) и `v0.1.1` (06.11.2026), то есть публичной истории меньше трёх недель
- версия плагина в `plugin.json` — 0.1.1

Шум вокруг проекта большой: 43 репозитория с похожим именем, включая форки под DeepSeek Harness (`dsh-egm`, `dsh-elephant-goldfish-model`). То есть идею уже растащили по средам.

## Что внутри

Семь скиллов (размер SKILL.md в байтах — по нему видно, где основная работа):

- `egm-bootstrap` — 23 889: описать существующую кодовую базу
- `egm-brainstorm` — 15 205: исследовать идею, спорить о компромиссах
- `egm-draft` — 17 479: писать спеку по секциям с паузой на фидбек
- `egm-review` — 24 257: протокол ревью в пять фаз
- `egm-review-loop` — 10 325: цикл ревью для произвольных документов
- `egm-resolve` — 8 541: разобрать находки
- `egm-drift-report` — 3 169: расхождение кода и дизайна

Персоны в `agents/` — восемь ревьюеров плюс оркестратор и синтезатор: `zoom_out`, `comprehension`, `design_critic`, `structural`, `style`, `implementation_readiness`, `inventive_catalyst`, `codebase_details`. Пять фаз ревью: первичный zoom-out, понимание, критика дизайна, промежуточный zoom-out, готовность к реализации.

Отдельно лежит `resources/document_standards/` — пять стандартов документов: `heilmeier-standard`, `zoom-out-standard`, `feature-spec-standard`, `implementation-readiness-standard`, `re-implementation-standard`. Это не промпты, а требования к форме документа, и они переносимы сами по себе.

В `egm-review/SKILL.md` прописаны правила поведения, которые интересны сами по себе: артефакт сначала в файл, а не в чат; простой язык без рекламных прилагательных; «никогда не соглашайся по умолчанию»; запрет на лесть и на извинения при исправлении. То есть авторы сознательно строят агента, который спорит.

## Где работает

Заявлены: ChatGPT desktop, Codex desktop и CLI, Antigravity (CLI, App, расширение для IDE), Claude Code, Claude Cowork, Copilot, Cursor, Muse, omp. Для opencode есть экспериментальный адаптер `adapters/opencode/install.py`: он собирает бандл из `skills/`, `agents/`, `resources/`, `docs/` и регистрирует восемь ревьюеров как субагентов с правами `*: deny`.

Ставится только целым плагином: «Skill-only installers that copy `skills/` alone break EGM», потому что скиллы читают `agents/` и `resources/` во время работы.

## Главное ограничение: нужны свежие субагенты

Ревью требует именно **свежего контекста**. В `SKILL.md` прямо сказано: если у среды нет инструмента субагентов — остановиться и сказать пользователю, что «ревью в том же контексте не является Goldfish-ревью». В Claude Code это `Agent`, в Codex `spawn_agent`, в Antigravity `invoke_subagent`.

## Что с Hermes Agent

Hermes не поддержан, но работа в этом направлении идёт и она задокументирована.

- **Issue #116** «Add support for Hermes, OpenClaw, and Delta» — открыт 23.10.2026, автор `trusktr`, комментариев нет.
- **PR #119** — закрытый дизайн-этап (Stage 1), добавил `docs/designs/multi_harness_support.md` на 151 строку. Статус в самом документе: «Stage 1 design proposal; native contracts and live runs unverified».

Что этот документ говорит про Hermes дословно по смыслу:

- в Hermes есть `delegate_task(goal, context)`, и дети получают **свежие беседы**, но **наследуют доступ к инструментам** и могут получать контекст проекта из рабочего пространства;
- проверить и доказать нужно: обнаружение пакета, точную установленную версию, загрузку персон, **подавление контекста проекта** и **принудительные права только на чтение**;
- отдельно предупреждение: не предполагать наличие `hermes.spawn` или фильтра инструментов на уровне вызова, как в Claude.

То есть барьер не в установке, а в изоляции: «золотая рыбка» обязана быть read-only и без родительского контекста, иначе ревью превращается в самопохвалу. В Hermes `delegate_task` фильтра инструментов не имеет — значит требование выполняется только договорённостью в тексте задачи, а не контролем среды.

## Надо ли нам

**Ставить сейчас — нет.** Причины конкретные:

1. Адаптера под Hermes нет, есть только дизайн-этап. Установка «на глазок» сломает либо ресурсы плагина, либо ожидания скиллов.
2. Ключевое требование EGM — принудительная изоляция ревьюера — в Hermes не обеспечивается технически. Ревьюер с доступом к записи может «поправить» проверяемый документ вместо того, чтобы сообщить о проблеме.
3. Проекту меньше трёх недель публичной истории, 77 открытых issues, версия 0.1.1. Ставить в контур, где мы уже ловим регрессии через тесты, рано.

**Что взять бесплатно и без установки:**

- восемь персон-ревьюеров как готовый чеклист для `delegate_task`: `zoom_out`, `comprehension`, `design_critic`, `structural`, `style`, `implementation_readiness`, `inventive_catalyst`, `codebase_details`. Тексты промптов лежат в `agents/*.md` под Apache-2.0;
- пять стандартов документов из `resources/document_standards/` — особенно `heilmeier-standard` (вопросы, на которые должен отвечать любой проект) и `zoom-out-standard`;
- правило «артефакт в файл, а не в чат» и запрет на лесть — у нас это уже работает как привычка, но у EGM оно записано формально.

**Проверять стоит за issue #116.** Если Hermes получит адаптер с настоящей изоляцией субагента, EGM станет применим напрямую.

## Чем это отличается от того, что у нас уже есть

У нас уже действует тот же принцип, только без плагина: работа одного агента проверяется другим, который не видел рассуждений первого. Например, при разборе регрессии `/files` разбор одной стороны проверялся по коду, диффу и живым замерам другой стороной, и это поймало две ошибки за день — несуществующий хеш коммита и HTTP-код 200 при мёртвой базе.

EGM добавляет к этому формальность: фиксированные роли ревьюеров, стандарты документов и обязательный цикл «находка → решение → повтор». Это дешёвая часть, её можно забрать хоть сегодня. Дорогая часть — изоляция — у нас пока на честном слове, а не на контроле среды.
