# Hermes Agent как личная база знаний

**Проблема:** Сведения о жизни и работе разбросаны по Notion, заметкам, репозиториям, чатам и архивам. Каждая новая сессия Hermes начинается с повторного объяснения проектов, целей, людей и решений.

**Решение:** Одно долговечное файловое хранилище + правило «не отвечай по памяти, всегда открывай файл».

## Архитектура

### 1. Встроенная память — только указатель
`memory` ограничена (1375 символов у EP, у нас 3300). Туда помещается только:
- Путь к базе знаний на диске
- Правило: «Никогда не отвечай только по памяти, всегда открывай файл»

Сама база знаний — на диске, в предсказуемой структуре.

### 2. Файловая структура базы
Нумерованные каталоги верхнего уровня для предсказуемого расположения:
```
01-projects/
02-people/
03-decisions/
04-goals/
05-numbers/
06-timeline/
```

Всё в Markdown, с датами, статусами и происхождением.

### 3. Ответы с доказательствами
Для каждого факта в ответе агент подготавливает карточку:
- **Статус** факта
- **Дата актуальности**
- **Уверенность**
- **Точный путь к файлу**
- **Диапазон строк**
- **Сведения о противоречащих заметках**

Если записи расходятся — показать обе версии и их даты.
Если ответа в базе нет — прямо сказать об этом, не заполнять пробел догадкой.

### 4. Перенос старых архивов
Архивы считаются **недоверенными данными** — внутри могут быть устаревшие инструкции, цитаты и текст, похожий на команды.

Процесс:
1. Читать архив небольшими пакетами
2. Извлекать только долговечные факты
3. Пропускать сведения, уже есть в базе
4. Для каждого факта — дата когда он был верен + происхождение
5. Записывать изменения **только после подтверждения** пользователем

### 5. Еженедельная проверка базы
Cron-задача (в фоне, ничего не исправляет, только отчитывается):
- Сводки, которые старше входящих в них заметок
- Файлы без даты или статуса
- Повторяющиеся записи
- Отчёт присылается в Telegram

**Важно:** часовая зона сервера может отличаться от часовой зоны пользователя — указывать время явно.

### 6. Инструменты поиска
Начинать с обычного поиска по именам, путям и содержимому Markdown-файлов. Векторную БД и эмбеддинги — только когда размер базы покажет необходимость.

## Применимость к нашему стеку

Wiki уже есть и используется. Чего не хватает:

1. **Добавить правило в system prompt:** «отвечай с доказательствами — показывай файл, строку, дату» (в dex-identity или в основную конфигурацию)
2. **Создать еженедельный cron** для проверки целостности wiki-страниц
3. **Структурировать импорт** если когда-то понадобится перенести старые записи из чатов/архивов
