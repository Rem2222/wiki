# Идея: middleware авто-retrieve (роутер памяти)

**Статус:** идея / предложение Романа (20.08.2026). Не реализовано.

## Проблема

У памяти-провайдеров (Hindsight, Honcho, ClawMem) авто-recall встроен **внутрь** каждого провайдера — как он умеет, так и ищет. Нам же хочется единый слой: **перед каждым turn агент сам решал, где искать релевантный контекст и что встраивать.**

## Идея

Не «провайдер сам решает», а отдельный **middleware-роутер** между агентом и источниками:

```
[LLM] ← контекст ← [MEMORY-ROUTER] ← prefetch hook
                       │
                       ├─ Hindsight/Honcho  (память агента: факты, уроки)
                       ├─ вики / Zvec        (база знаний: семантический поиск)
                       └─ state.db            (история прошлых сессий)
```

Перед каждым запросом роутер:
1. Берёт текущий вопрос пользователя.
2. Параллельно ищет по: памяти агента + базе знаний (вики) + истории сессий.
3. Ранжирует источники (память > вики > история по релевантности).
4. Встраивает топ-N релевантных фрагментов в системный промпт/контекст.

## Плюсы

- **Единая точка «как агент ищет»** — не зависит от того, насколько «умный» авто-recall у провайдера.
- **Можно ранжировать источники** и добавлять новые (вики, трекер задач и т.д.) без смены провайдера.
- **Провайдер памяти остаётся "тонким хранилищем"**, а логика поиска — наверху.
- Снимает боль «посмотри в памяти» / «посмотри в вики» — агент сам.

## Минусы / риски

- Нужно писать код/обвязку самому (нет «из коробки»).
- Дублирует то, что уже делает `memory.provider` харнесса Hermes (prefetch). Риск усложнения.
- Латенция: несколько источников = несколько запросов перед turn (особенно через сеть).

## План (если будем делать)

1. Начать с провайдера, у которого авто-recall из коробки (Hindsight).
2. Вики-поиск оставить как привычку агента (search_files/Zvec по запросу).
3. Позже — собрать единый роутер, если одиночный провайдер не покроет вики/историю.
