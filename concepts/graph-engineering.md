# Graph Engineering

**Суть:** Одна LLM-сессия не тянет большие задачи — контекст забивается, зависимости запутываются. Решение — описывать работу как **граф**, а не как линейную цепочку.

## Базовые элементы графа

| Элемент | Описание |
|---|---|
| **Node** (узел) | Субагент, функция, поиск, тест, компилятор, shell-команда или человек. Получает ограниченное задание, возвращает результат известной формы |
| **Edge** (ребро) | Зависимость между узлами — какие данные нужны следующему узлу и какое условие разрешает переход |
| **State** (состояние) | План, результаты, ошибки, попытки, бюджет, пути к worktrees, коммиты. Выносится из контекстного окна агента в файлы, БД или журнал |
| **Gate** (проверка) | Решает, можно ли считать узел завершённым. Зелёный exit code тестов надёжнее фразы агента «всё готово» |

## Ключевые паттерны

```
fan-out → barrier → fan-in
  ├─ исследование архитектуры
  ├─ анализ тестов
  └─ документация API
         ↓
      сводка → план → реализация → ревью
```

- **Fan-out** — задача делится на независимые части
- **Barrier** — ожидание всех веток (или quorum)
- **Fan-in** — сборка результатов в одной точке
- **Diamond** — split → parallel → reduce → synthesize
- **Worktree isolation** — каждый пишущий агент в своей копии, интеграция — последовательно

## Практические правила

1. Параллелить **чтение** (исследование, аудит), последовательно — **запись** (реализацию)
2. Исполнитель не объявляет свою работу завершённой — нужен независимый reviewer
3. Цикл «тесты упали → исправление» — с ограничением (max 3 попытки)
4. Если два шага независимы — их можно выполнять параллельно
5. Если оба меняют одни файлы — нужна изоляция (worktree) или последовательное выполнение

## Реализации

| Инструмент | Как реализован граф |
|---|---|
| Claude Code | Dynamic Workflows — JavaScript-сценарий, `parallel()`, `agent()`, `if/for`. Результаты в переменных скрипта, субагенты в отдельных контекстах. Сохраняется как `.claude/workflows/` и запускается slash-командой |
| Codex CLI | Нативные субагенты + Ultra. Роли в `config/agents.toml` (`explorer`, `worker`, `reviewer`). Граф возникает runtime, topology не закреплена сценарием |
| codemcp | Claude-совместимые workflow на Codex. Поддержка parallel, sequence, map, JSON Schema, loops, token budget, `isolation: "worktree"` |
| codex-workflow-engine | Отдельный runtime для Codex |
| claude-code-on-codex | Перенос Claude Workflow на Codex |

## Когда граф избыточен

- Локальная правка одного файла
- Простой рефакторинг без зависимостей
- Быстрый вопрос/ответ

## Практическая лестница

1. Начать с узкого графа: 2 read-only исследователя → 1 writer в worktree → реальные тесты → свежий reviewer
2. После нескольких запусков добавить durable state, новые узлы, ветвление
3. Если процесс повторяется — зафиксировать как исполняемый сценарий

## Релевантность к Dex/Hermes

Hermes уже поддерживает параллельную делегацию через `delegate_task`:
- Batch mode (до 3 параллельных subagent) — это fan-out + barrier + fan-in
- `role: orchestrator` — позволяет строить многоуровневые графы
- Работа через Gateway API — state может храниться вне контекста

Можно развить: добавить worktree-изоляцию, формальные gates (exit code → решение), durable workflow state, повторяемые сценарии в стиле Claude Workflows.
