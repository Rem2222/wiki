# CodexBar-Win: варианты перевода с Python на нативный стек (2026)

## Вопрос

CodexBar-Win — приложение на Python (customtkinter для окна и настроек, PyQt6 для плавающих виджетов, pystray для трея, Playwright для парсинга Alibaba). Хочется понять, на что его переводить, чтобы получить нативное приложение под Windows: меньше вес, нормальный трей, автозапуск, подпись, отсутствие Python у пользователя.

Данные по версиям — на 02.11.2026.

## Варианты

### Tauri 2 — Rust + системный WebView (2.12.4, 21.10.2026, 112 438 ⭐, Apache-2.0)

Оболочка на Rust, интерфейс — HTML/CSS/JS в WebView2 (в Windows 11 он уже стоит, в Windows 10 ставится вместе с приложением). Бинарник 3–10 МБ, трей и автозапуск есть в API, IPC между Rust и интерфейсом, мобильные таргеты в этой же версии.

Плюсы: самый маленький вес, зрелая экосистема (112 тысяч звёзд), огромное количество готовых плагинов (store, updater, notification, autostart, single-instance), интерфейс можно верстать как веб — а у нас уже есть навык и unslop-скилл именно про HTML/CSS. Трей, уведомления и автозапуск закрываются плагинами.

Минусы: WebView2 — это не «нативный контрол», а браузер, то есть по памяти приложение ближе к Electron, чем кажется (40–120 МБ против 30–60 у Qt); нужен Rust для бэкенда; парсинг сайтов с авторизацией придётся переписывать (нет Playwright — есть headless через CDP или отказ от Playwright в пользу API, как мы уже сделали для OpenCode).

### Avalonia 12 — C#/.NET (12.1.5, 02.11.2026, 31 747 ⭐, MIT)

Полноценный нативный рендер (Skia), XAML, MVVM, одна кодовая база на Windows, macOS и Linux. .NET 10 LTS актуален, .NET 11 выходит 10.11.2026 как STS.

Плюсы: настоящий нативный UI без WebView; C# — самый прямой путь для Windows-приложения (трей, автозапуск, подпись, установщик через WiX/MSIX); отличный отладчик и профайлер; библиотеки HTTP/JSON/крипто в стандартной поставке; self-contained сборка не требует .NET у пользователя.

Минусы: язык и экосистема новые для Романа; XAML — отдельный навык, верстка не переиспользуется с HTML; вес self-contained 40–70 МБ (trimmed меньше, но с оговорками).

### Wails 3 — Go + WebView (v3.1.0, 01.11.2026, 36 918 ⭐, MIT)

Тот же принцип, что у Tauri, но бэкенд на Go: фронт — веб, бэкенд — Go, трей и системные вызовы через Go. v3 вышел 26.10.2026, через неделю — 3.1.0, то есть версия совсем свежая.

Плюсы: Go проще Rust, сборка одного exe, вес близок к Tauri, HTTP-клиенты и парсинг в Go удобны.

Минусы: v3 только что вышел — риск сырости; экосистема плагинов меньше; WebView2 те же 40–120 МБ памяти; документации по v3 пока немного.

### PySide6 / Qt 6.12 LTS — остаться в Python, но сменить UI (PySide6 6.12.0, 09.10.2026, Qt 6.12 LTS)

Не перевод языка, а перевод UI: customtkinter и PyQt6 заменяются одним Qt-стеком с нормальными виджетами, треем (`QSystemTrayIcon`), стилями через QSS.

Плюсы: минимум переписывания — фетчеры, парсеры, логика остаются как есть; Qt даёт нативный вид и трей из коробки; LGPL, коммерческая лицензия не нужна; переиспользуется весь существующий код на 100%.

Минусы: Python у пользователя либо PyInstaller-сборка на 60–120 МБ (и ложные срабатывания антивирусов — известная беда PyInstaller); старт приложения медленнее; GIL мешает тяжёлому парсингу в фоне; проблема двух UI-библиотек (tk + Qt) решается, но остаётся Python-зависимость.

### Остальные, для полноты

- **Dioxus 0.7.10** (Rust, 39 579 ⭐) — UI на Rust с собственным рендером, но 0.7 всё ещё до 1.0
- **Slint 1.18.1** (Rust/C++, 24 367 ⭐) — декларативный UI для встраиваемых и десктопа, лицензия смешанная (GPL/коммерческая для части сценариев), для нас неудобно
- **Flutter Windows** — рисует всё сам, вес 20–30 МБ, но Dart и «не нативный» вид; для утилиты в трее избыточно
- **C++/Qt 6** — максимум контроля, но стоимость разработки выше всех прочих вариантов

## Сравнение по нашим критериям

- Вес и память: Tauri и Wails (3–10 МБ на диске, 40–120 МБ RAM из-за WebView) → Avalonia (40–70 МБ на диске, 60–100 МБ RAM) → PySide6+PyInstaller (60–120 МБ, старт медленнее)
- Трей, автозапуск, уведомления: у всех есть, у Avalonia и Qt — родные API, у Tauri/Wails — плагины
- Переиспользование текущего кода: PySide6 близко к 100%, Avalonia — 0% (переписывать всё), Tauri/Wails — фетчеры на Rust/Go заново, интерфейс заново на вебе
- Скорость получения результата: PySide6 — дни, Tauri/Avalonia/Wails — недели
- Риск: PySide6 — низкий (тот же Python), Avalonia — средний (новый язык, стабильный фреймворк), Tauri — низкий-средний (зрелый), Wails v3 — высокий (релиз недельной давности)

## Что рекомендую

Развилка простая: цель — **убрать Python** или **получить нормальный UI**.

1. **Если цель — UI и скорость:** PySide6 6.12 поверх существующего кода. Фетчеры, парсеры, cookie-дешифратор и логика остаются, меняется только слой представления. Через unslop-проходы получаем аккуратный интерфейс сразу, без переписывания бизнес-логики. Сборка через Nuitka (лучше PyInstaller: меньше ложных срабатываний антивирусов, быстрее старт).
2. **Если цель — настоящее нативное приложение без Python:** **Avalonia 12 на C#/.NET 10 LTS**. Windows-первый стек, нативный рендер, трей и автозапуск родные, self-contained сборка не требует ничего у пользователя, MSIX-подпись и обновления штатные. Цена — переписать всё, включая парсеры (C# умеет HTTP и AngleSharp вместо Playwright).
3. **Tauri 2** — если хочется маленький бинарник и переиспользовать веб-навыки (в том числе unslop прямо по интерфейсу). Но память всё равно от WebView, а бэкенд на Rust придётся писать с нуля.
4. **Wails 3** — только если Go приятнее Rust; версия слишком свежая для рабочего инструмента.

Промежуточный путь, который часто оказывается лучшим: сначала привести UI в порядок на PySide6 (это и есть текущая задача по дизайну), а решение о смене языка принимать отдельно, когда интерфейс уже устраивает. Переписывать имеет смысл то, что уже нравится.
