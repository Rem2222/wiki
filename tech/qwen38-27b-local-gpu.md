# Qwen3.8-27B на домашней GPU — кейс и бенчмарки квантизации

## Модель

**Qwen3.8-27B** — dense 27B multimodal vision-language модель от Alibaba/Qwen (вышла 15 авг 2026).

| Параметр | Значение |
|---|---|
| Архитектура | Hybrid Gated DeltaNet + gated attention, 64 слоя |
| Контекст | 262K токенов (нативно), до 1M (расширенно) |
| Vision | Нативная поддержка изображений и видео |
| Лицензия | Apache 2.0 |
| BF16 размер | **55 ГБ** |

### Бенчмарки (Qwen self-reported, BF16)

| Бенчмарк | Qwen3.8-27B | Qwen3.6-27B | Claude Opus 4.6 Max |
|---|---|---|---|
| Terminal-Bench 2.1 | 73.0 | 63.4 | 78.2 |
| SWE-bench Pro | 61.7 | 53.5 | 53.4 |
| GPQA Diamond | 89.2 | 87.8 | 91.3 |
| IFBench | 79.5 | 69.1 | 62.5 |
| DeepSWE 1.1 | 42.2 | 13.3 | — |

27B dense модель приближается к Opus-class на coding/agentic бенчмарках — впечатляющий результат для своего размера.

## GGUF квантизации (Unsloth Dynamic v3.0)

Основной источник: [huggingface.co/unsloth/Qwen3.8-27B-GGUF](https://huggingface.co/unsloth/Qwen3.8-27B-GGUF)

### Таблица размеров

| Quant | Файл | Размер | Нужно памяти |
|---|---|---|---|
| **1-bit** | UD-IQ1_S | 6.2 ГБ | 7–8 ГБ |
| **2-bit** | UD-Q2_K_XL | 10.7 ГБ | 9–11 ГБ |
| **3-bit** | UD-Q3_K_XL | 13.1 ГБ | 12–14 ГБ |
| **4-bit** | UD-Q4_K_M | 16.5 ГБ | 17–19 ГБ |
| **4-bit** | UD-Q4_K_XL | 17.6 ГБ | 17–19 ГБ |
| **5-bit** | UD-Q5_K_M | 19.8 ГБ | 20–22 ГБ |
| **6-bit** | UD-Q6_K_M | 23.1 ГБ | 24 ГБ |
| **8-bit** | Q8_0 | 29 ГБ | 31 ГБ |
| **BF16** | Оригинал | 55 ГБ | 56 ГБ |

**Важно:** размер файла ≠ потребление памяти. KV-cache + runtime buffers добавляют 2–8 ГБ в зависимости от длины контекста.

## Бенчмарки квантизации (независимый тест, Quesma.com)

Автор потратил ~$3000 на аренду GPU (Modal) для тестов. Используется `llama.cpp` сборка от 16 авг 2026. KV-cache: F16, ~2.3 ГБ на 32K токенов.

| Quant | Результат | Сравнение |
|---|---|---|

> **Q4_K_M (17 ГБ) = BF16 (55 ГБ)** на всех трёх бенчмарках. Разница в размере — в 3.2 раза, разница в качестве — нулевая.

## Какой quant выбирать

| GPU | Рекомендация | Почему |
|---|---|---|
| 8 ГБ (GTX 1070 и т.п.) | 1-bit (6 ГБ) | Единственный вариант, 77% точности — для экспериментов |
| 12 ГБ (RTX 3060) | 2–3 bit | Заметный прирост над 1-bit, влезает |
| **16 ГБ (RTX 4080)** | **3-bit (13 ГБ)** | Чистая посадка на GPU, Q4 может потребовать offload |
| **24 ГБ (RTX 4090/5080)** | **4-bit Q4_K_M (17 ГБ)** | Sweet spot — 64K контекста, BF16-качество |
| 48 ГБ (L40S/A6000) | 5–6 bit | Дополнительная точность + длинный контекст |
| Mac M-series 64 ГБ | 6–8 bit | Unified memory даёт преимущество |

## Что происходит при квантизации — «отупление»

### Нелинейная деградация

Квантизация **не линейна**. Есть три зоны:

1. **Зона безопасности (Q4–Q8):** модель сохраняет качество. Шум в весах не влияет на предсказания — те же токены с вероятностью >95%
2. **Зона риска (Q2–Q3):** заметные потери на научных/сложных бенчмарках, но coding/agentic задачи остаются на уровне
3. **Обвал (1-bit):** модель теряет способность к рассуждению. Подлинно длинные цепочки рассуждений (thinking mode xhigh) ухудшают результат — модель «؊�сывается» до токен-лимита и выдаёт пустой ответ

### Почему Q4 работает так хорошо

Модель 27B имеет ~55 ГБ весов в BF16. Q4 сжимает до ~17 ГБ — это потеря 3.2x по размеру. Но:
- Не все слои одинаково важны — Unsloth Dynamic quantization сохраняет высокую точность в критических слоях
- Градиенты «перераспределяются» — шум в одних весах компенсируется точностью в других
- Для предсказания следующего токена критичны **относительные соотношения** весов, а не абсолютные значения

### Что ломается в 1-bit

При 1-bit каждый вес представляется одним битом (0 или 1 вместо float16). Это:
- Убивает **тонкие градации** в attention-механизмах
- Делает **reasoning chains** нестабильными — ошибка накапливается на каждом шаге
- Модель начинает **hallucinate** или выдавать **пустые ответы** на сложных задачах
- На GPQA Diamond — уровень случайного угадывания (~25%)

## Запуск на практике

### llama.cpp (максимальный контроль)

```bash
# Загрузка Q4_K_M с offload на GPU
llama-server -hf unsloth/Qwen3.8-27B-GGUF:Q4_K_M \
  -ngl 999 \
  -fa on \
  -c 65536 \
  --port 8080
```

### Ollama (проще)

```bash
ollama run unsloth/qwen3.8-27b:Q4_K_M
```

### Рекомендованные настройки сэмплирования

| Параметр | Thinking mode | Non-thinking |
|---|---|---|
| Temperature | 1.0 | 0.7 |
| top_p | 0.95 | 0.80 |
| top_k | 20 | 20 |
| presence_penalty | 0.0 | 1.5 |

## Релевантность для XE2690

Текущая карта пользователя — **GT 1030 2GB**. Qwen3.8-27B **неработоспособен** на этом оборудовании:
- Минимум для 1-bit: 8 ГБ памяти (GT1030: 2 ГБ VRAM + 64 ГБ RAM → теоретически возможно через CPU offload, но скорость будет ~0.5 tok/s — непригодно для использования)
- Рекомендуемый минимум: RTX 3060 12 ГБ (Q2–Q3) или RTX 4060 8 ГБ (1-bit only)

**Альтернатива для текущего железа:** Ollama qwen2.5:7b (уже установлена) — работает на CPU, 4.7 ГБ RAM, реальная производительность ~2–5 tok/s.
