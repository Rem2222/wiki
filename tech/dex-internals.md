# Dex — внутреннее устройство

Разобрано по исходникам 30.09.2026. Коммит `ef3030b`.

## TL;DR

**Dex — не агент** в современном смысле: нет tool-calling, нет скиллов, нет способа
для LLM позвать инструмент самому. Это **три независимых Python-процесса**, которые
лежат рядом с Hermes, дёргают один LLM одним HTTP-запросом и общаются между собой
через файлы и SQLite.

При этом **доступ к системе у него есть** — но только у процесса `heartbeat`, и только
через заранее прошитые `df`, `apt`, `systemctl`, `docker ps` и обход `/root/backups`.
Процесс `dex-poller` (то, чем общаются в Telegram) в систему **не смотрит вообще**.

## Три процесса

| Процесс | Файл | Роль |
|---|---|---|
| `dex-poller` (systemd user) | `dex_poller.py`, 400 стр. | Telegram ↔ LLM. `while True`, пауза **3 с**: `getUpdates` → `process_message` → `call_hermes` → `sendMessage`. Offset в `.poller_offset`. |
| `dex-control` (systemd user) | `dex_control.py`, Flask | Дашборд и API на `127.0.0.1:3333`, наружу `rem2222.top/dex/` (nginx + Authelia). Свой venv `~/.hermes/proactive/venv`. |
| `dex-heartbeat` (cron) | `heartbeat.py`, 551 стр. | Тик каждые **10 мин**, режим `no-agent`. Пуск: `dex-tick.sh` → флаг `DISABLED` → `python3 heartbeat.py`. |

Красная кнопка `DISABLED` общая для всех трёх.

## Два разных «мозга»

Это самое важное: под именем «Dex» живут **две разные системы**.

### Общение (poller)

```
identity.yaml      → system prompt (+ блок состояния + правила честности)
sessions.db        → последние 30 сообщений (15 обменов)
+ твоё сообщение   → ОДИН LLM-запрос → ответ в Telegram
```

Одношаговый: один запрос, один ответ. **Нет цикла, нет инструментов.**

### Сердцебиение (heartbeat)

```
состояние (тик, фокус, драйвы, долги, последние 3 тика)
→ LLM отвечает ОДНИМ СЛОВОМ из белого списка
→ if/elif исполняет готовую функцию
```

Белый список: `check_updates, check_backups, check_disk, check_tools,
check_services, explore_interest, none`. Всё прочеe отбрасывается как `bogus`.

## Луп: 7 шагов

```
1. Флаг DISABLED?        → спим
2. tick_count += 1, токен, identity, БД
3. Контекст: последние 3 тика, фокус, драйвы, просроченные duties
4. Сборка промпта
5. call_llm(max_tokens=20) — ответ одним словом
6. Валидация по белому списку
7. execute_*() → запись тика → отчёт в Telegram или дайджест
```

Интервалы обязанностей: диск и сервисы — **час**, бэкапы / обновления /
инструменты — **сутки**. Просроченное подставляется в промпт строкой
«Пора проверить: …», но решение всё равно за LLM.

## Исполнители: честная оценка

| Команда | Состояние | Что делает |
|---|---|---|
| `check_backups` | ✅ реально | Скан `/root/backups` на `*.sql.gz`, `*.tar.gz` → возраст самого свежего |
| `check_updates` | ✅ реально | `apt list --upgradable` |
| `check_disk` | ✅ реально | `df -h /` |
| `check_services` | ⚠️ частично | Проверяет **только `dex-poller`** + считает docker-контейнеры. Остальные ~20 сервисов не проверяются |
| `check_tools` | ❌ заглушка | «поиск инструментов запланирован, пропускаю этот тик» |
| `explore_interest` | ❌ заглушка | Случайный интерес из `identity.yaml` → «посмотрю что нового в …», без исследования |

**2 из 7 действий не делают ничего.**

## Драйвы (модель v2, внедрена 30.09)

| Событие | Эффект |
|---|---|
| простой тик (`none`) | `curiosity +0.10` |
| просроченная обязанность | `diligence +0.05` |
| выполнена обязанность | `diligence −0.30` |
| `explore_interest` | `curiosity −0.40` |
| другое действие | `curiosity −0.10` |
| границы | пол `0.10`, потолок `1.00` |

Модель утверждена Романом 30.09: **потребность копится, пока не выполнена,
и сбрасывается действием**.

> **Почему понадобилась правка.** Изначальная логика была перевёрнута: драйв
> увеличивался **после** выполненного действия и **нигде не убывал**. За 1371 тик
> оба упёрлись в `1.0` и стали константой — то есть делал он что угодно,
> а «сильно хотел» всегда.
>
> Разовый сброс `migrate_drives()` (маркер `drives_v2`) перевёл `1.0/1.0 → 0.4/0.4`.

Голые числа LLM игнорирует, поэтому при `≥ 0.7` в промпт добавляется прямая
подсказка («выбери explore_interest» / «выбери обязанность»).

## Уведомления и дайджест

С 30.09 в Telegram уходит **каждое действие** (обещание «отписываться на каждый тик»),
а не только аномалии. Кулдаун на идентичный текст держит поток в **~14–15 сообщений/сутки**
(не 49 — одинаковые результаты глушатся).

| Действие | Кулдаун |
|---|---|
| `check_disk`, `check_backups`, `check_services` | 6 часов |
| `check_updates`, `check_tools` | 24 часа |

Аномалии (`≤10G` свободно, «нет файлов», `inactive`/`failed`) идут приоретным форматом.
Дайджест — сводка раз в сутки, до 12 записей, с дедупликацией.

## Память: четыре хранилища

| Хранилище | Содержимое |
|---|---|
| `identity.yaml` (2.6 КБ) | Личность: имя, роль, 9 черт, 8 интересов, 5 обязанностей. Основа system prompt |
| `agent.db` (1.5 МБ, WAL) | `state` (счётчики, фокус, драйвы, кулдауны, дайджест), `llm_log` (~1300 записей), `tasks` (**пуста**), `config`, `ticks_meta`, `vec_ticks` |
| `sessions.db` (77 КБ) | Диалоги: `chat_id, role, content, ts`. В промпт — последние **30** |
| `tick_history.jsonl` (152 КБ) | Append-only журнал тиков: номер, действие, результат, время |

### Векторная память (sqlite-vec + bge-m3)

`vec0.so` (159 КБ, из wheel `sqlite_vec 0.1.9`, **без** `pip install` — тот упирается
в PEP 668) лежит в `~/.hermes/proactive/lib/` и подключается через
`connection.load_extension()`.

- таблица `vec_ticks` — `vec0(embedding float[1024])`, `rowid` = номер тика
- эмбеддинги — `bge-m3` через Ollama `:11434/api/embed`, 1024 измерения
- сборка — `vec_build.py`

**Ключевой приём: дедупликация.** 1362 тика дают всего **~69 уникальных** строк
`action: result` (857 тиков `none` = 4 текста). Эмбеддим каждую строку один раз
и раздаём вектор всем тикам с этим текстом: 69 эмбеддингов вместо 1362 —
минуты вместо двух часов.

> **Почему не сразу `pip install sqlite-vec`.** Системный Python под PEP 668
> (`externally-managed-environment`). Решение — достать `vec0.so` из wheel
> и подключать по пути. Не трогает системное окружение.

## Чат: путь одного сообщения

```
Telegram → getUpdates (каждые 3 с)
  → process_message:
      /start            → заготовленное приветствие
      /status, /state   → блок состояния (тик, фокус, драйвы, 5 тиков)
      любое другое /…   → «команда пока не реализована»
      обычный текст:
        identity.yaml + состояние + правила честности → system prompt
        sessions.db → последние 30 сообщений
        → LLM (один запрос, без инструментов)
        → ответ в Telegram, обе реплики в sessions.db
```


## Диагностика 30.09: откуда брались странные ответы

Разобрано три отдельных причины, **не** связанных с размером контекста
(промпт всего ~800 токенов, у модели контекст огромный):

1. **Провайдерная ошибка Google.** Воспроизведено чистым запросом без истории:
   просьба «открой файлы, найди правила» → сервер Google отвечает
   *«Я не могу использовать Workspace, потому что необходимые параметры Gmail
   отключены»*. Прокси `gemini-web2api` инструменты **не подключает**
   (берёт `req.get("tools")`, а их нет), то есть ошибка приходит **извне**.
   В `sessions.db` таких ответов 5. Теперь: ловим → повтор → честный ответ.
2. **Конфабуляция про sqlite_vec.** Dex утверждает, что прикрутил векторную
   память. Проверено: в БД не было ни одной виртуальной таблицы, расширение
   не установлено, в коде ноль упоминаний. Фраза лежит **в его собственном
   system prompt** — `identity.yaml:32` (интерес) и `README.md:53`
   («Целевая: TencentDB Agent Memory (sqlite-vec …)», этап 5, статус 🔜).
   Он пересказывает план как свершившийся факт.
3. **Отсутствие ground truth.** В диалоге были только `identity.yaml` + 10 реплик,
   поэтому каждый ответ он достраивал заново и **противоречил предыдущему**
   («искал по индексам» → «я всего лишь текстовый ИИ, задача не для меня»).

## Конфигурация

```bash
# ~/.hermes/proactive/.env (права 600)
DEX_API_URL=http://127.0.0.1:8083/v1/chat/completions   # gemini-web2api
DEX_API_KEY=***
DEX_MODEL=gemini-3.5-flash
DEX_BOT_TOKEN=***            # @Jawl_Moishe_bot

# Cron
dex-heartbeat   every 10m   no-agent → dex-tick.sh → heartbeat.py

# Сервисы (systemd --user)
dex-poller.service    enabled + active
dex-control.service   enabled + active   venv: ~/.hermes/proactive/venv (flask 3.1.3)

# Красная кнопка
touch ~/.hermes/proactive/DISABLED     # усыпляет всё
rm    ~/.hermes/proactive/DISABLED     # пробуждение
```

Провайдер читается **обоими** процессами из одного `.env` — сменить модель или
endpoint можно без правки кода.
