# AnythingLLM vs Dify vs RAGFlow

**Они не конкуренты в одной категории**, поэтому «выбрать по звёздам» — ошибка. Разные задачи:

- **AnythingLLM** — «поставить и через 10 минут задавать вопросы своим документам». Локально-первичный workspace.
- **Dify** — платформа AI-приложений: визуальные workflow, агенты, API, наблюдаемость. RAG здесь — один из блоков.
- **RAGFlow** — RAG-движок с упором на **разбор** документов (таблицы, сканы, вёрстка, цитаты).

## Ресурсы — то, что решает на нашем железе

| | AnythingLLM | Dify | RAGFlow |
|---|---|---|---|
| Минимум | 4 ядра / 8 ГБ (десктоп — без Docker) | 2 ядра / 8 ГБ dev, 4/16 ГБ прод | 4 ядра / **16 ГБ**, рекоменд. 32 ГБ |
| В простое | **~1.1 ГБ** | ~9 ГБ (16 контейнеров) | тяжело: Elasticsearch + MinIO + Redis |
| Диск | десятки ГБ | десятки ГБ | от **~100 ГБ** |
| Порог входа | минуты | 30–60 мин, полдня с доменом/HTTPS | ~полдня, плюс тюнинг `vm.max_map_count` |
| Векторная БД | LanceDB (встроенная) | Weaviate (в дефолтном compose) | Elasticsearch / Infinity |

**Наш VPS: 11 ГБ RAM (свободно ~7), диск 96 ГБ занят на 82% (свободно 18 ГБ).** Отсюда вывод прямой: RAGFlow не влезает по диску и памяти, Dify — на грани (16 контейнеров, ~9 ГБ в простое при 7 свободных). AnythingLLM — единственный, кто реально встаёт рядом с Hermes и Multica без переезда.

## Что выбрать

- **Документы простые, нужен быстрый чат по ним, железо скромное** → AnythingLLM
- **Нужны workflow, агентные цепочки, внешний API, несколько приложений** → Dify (и готовить 16 ГБ)
- **PDF с таблицами/сканами/сложной вёрсткой, нужны цитаты по страницам** → RAGFlow (и отдельная машина)

## Общее для всех трёх: качество RAG решают две вещи

**1. Модель эмбеддингов** (менять потом = переиндексировать всё):

- `nomic-embed-text` — 137M, 768 измерений, 8k контекст, ~274 МБ. Быстрый, CPU-дружелюбный, хорош для английского и «просто чтобы заработало».
- `bge-m3` — 568M, 1024 измерения, 100+ языков, 8k контекст, сразу dense+sparse+multi-vector. Для **русского** и мультиязычных документов заметно точнее, но медленнее и ~1.5 ГБ памяти.

Правило: английский/личные заметки → nomic; русский, юридические/технические термины, смешанные языки → **bge-m3**.

**2. Размер чанка:**

- обычный текст: 500–1000 токенов, перекрытие 10–20%
- договоры, тех. руководства, отчётность: 1500–2000 (иначе ответ рвётся между блоками)
- письма, тикеты, короткие записи: 300–500

## Питфоллы

- **Приватность определяется не названием инструмента, а тем, где работает модель.** Любой из трёх с облачным эмбеддингом отправляет куски документов наружу. Хочешь «данные не выходят» — локальными должны быть и LLM, **и** эмбеддинги.
- Смена модели эмбеддингов = полная переиндексация. У AnythingLLM есть подсказка, у Dify/RAGFlow триггерить вручную; на тысячах документов это часы. Определяйся до загрузки.
- Dify после каждого апгрейда: сверять `.env.example` со своим `.env` и переприменять правки к новому `docker-compose.yaml` (в релизах добавляются сервисы), бэкапить тома PostgreSQL и векторной БД.
- RAGFlow: без поднятого `vm.max_map_count` Elasticsearch просто не стартует — классическая потеря часа на пустом месте.
