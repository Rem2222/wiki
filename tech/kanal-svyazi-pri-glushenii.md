# Канал связи с агентом при глушении интернета

## Задача (со слов Романа, 10.10.2026)

1. Работает периодически с телефона. Мобильный интернет **глушат**, доступны только
   сайты и приложения из **белого списка**: VK, Яндекс, MAX, TrueConf и подобные.
2. **Telegram глушат**, а общение с агентом идёт именно через Telegram.
3. Нужен канал связи с агентом при включённых глушилках.

## Главный принцип решения

Обход (VPN, прокси, WARP) здесь **не работает по определению**: в режиме белого списка
доступны только перечисленные ресурсы, и VPN-эндпоинт в список не входит.

Зато работает другой принцип:

> **Наш VPS не обязан быть в белом списке.** Достаточно, чтобы мессенджер был доступен
> с телефона (он в белом списке), а VPS общался с его API по обычному интернету.

Проверено фактически с VPS (Contabo, Франция):

- `api.vk.com` → **200** (метод `messages.getLongPollServer` отвечает «token required»,
  то есть эндпоинт живой)
- `botapi.max.ru` → **401** `{"code":"verify.token","message":"No access token"}` — работает
- `platform-api.max.ru` → **401** — работает
- `platform-api2.max.ru` → **TLS-ошибка** (`ssl_verify_result=20`) — см. ниже про сертификат

## Вариант 1. VK — без барьеров (рекомендуемый)

**Почему VK:** сообщество и бота-сообщества может создать **любой пользователь**, без
верификации и без юридического лица. Бесплатно. VK есть в белом списке Минцифры.

**Готовый плагин Hermes:** `web3blind/hermes-vk-platform` — MIT, версия 0.2.6, свежий пуш
09.10.2026, Python, есть тесты и docs.

Что умеет:

- входящие через **VK Group Long Poll** (`message_new`, `message_edit`) — **не требует
  публичного HTTPS/webhook**, работает за NAT
- исходящие через `messages.send`; личные и групповые чаты (`peer_id = 2000000000 + chat_id`)
- allowlist по пользователям и чатам (`VK_ALLOWED_USERS`, `VK_ALLOWED_PEERS`,
  `VK_ACCESS_POLICY`, `VK_ALLOWED_USERS_BY_PEER`) — важно, чтобы агент не был открыт всем
- **cron-доставка** через `VK_HOME_CHANNEL` — то есть в VK можно получать и регулярные отчёты
- редактирование сообщений для бабблов прогресса инструментов
- медиа в обе стороны: фото, документы, голосовые, аудио, видео
- TTL-дедупликация повторных `message_new` после переподключения
- реакция-акки (прогресс → 👍/👎)
- **нет обязательных сторонних зависимостей** — адаптер использует стандартную библиотеку Python
- Markdown конвертируется в plain text (в VK нет `parse_mode`)

**Что нужно сделать (делает Роман, не агент):**

**Где создать сообщество (частая путаница):** сообщества создаются **не в приложении
«VK Мессенджер»** — это отдельное приложение только для переписки. Нужно основное
приложение **ВКонтакте** или сайт.

- сайт: `vk.com` → раздел **Сообщества** → кнопка **Создать сообщество**
  (прямая ссылка `https://vk.com/groups?act=create` — жива, отдаёт 302 на логин)
- мобильное приложение **ВКонтакте**: раздел **Сообщества** → **Создать сообщество**
  (по официальному FAQ `vk.ru/faq18025`: «Откройте раздел Сообщества и нажмите кнопку
  Создать сообщество. Укажите название сообщества, выберите тематику»)

> ⚠️ **ВАЖНО (проверено на живом экране 10.10.2026):** в **мобильном приложении**
> разделов **«Работа с API»** и **«Настройки для бота → Возможности ботов» НЕТ. В разделе
> «Сообщения» управления сообществом в приложении есть только тумблеры «Сообщения
> сообщества», «Push-уведомления» и поле «Приветствие» — этого мало для бота.
> Все настройки API делаются **в веб-версии ВКонтакте**.
>
> **С телефона это тоже выполнимо:** открыть `vk.com` в браузере телефона и включить
> «Версию для ПК» — Chrome: ⋮ → «Версия для ПК»; Safari: «аA» → «Полная версия сайта».
> Либо сделать с компьютера (домашний XE2690, рабочий терминал).

1. Создать сообщество VK
2. **Ключ доступа:** в веб-версии открыть сообщество → кнопка **«Управление»** (под обложкой)
   → **«Дополнительно» → «Работа с API»** → вкладка **«Ключи доступа»** → **«Создать ключ»**.
   Отметить права: «доступ к управлению сообществом» + права на сообщения. Ключ передаётся
   в заголовке `Authorization: Bearer <ключ>`; публиковать его нельзя
3. **Long Poll:** там же, вкладка **«Long Poll API»** (рядом с «Ключи доступа» и
   «Callback API») → переключить в **«Включено»** → в **«Типы событий»** включить
   **«Сообщение новое»** (`message_new`), а также `message_edit` и `message_event`
   (последнее — для callback-кнопок). Без этого бот запустится и будет молчать
4. **Возможности ботов:** Управление → **«Настройки для бота»** → раздел
   **«Возможности ботов»** → включить. Переключатель **«Бизнес-инструменты»** для бота
   не нужен — оставить выключенным
5. Прописать в `~/.hermes/.env`: `VK_GROUP_TOKEN`, `VK_GROUP_ID` (числовой id без минуса,
   цифры после `club` в адресе), `VK_ALLOWED_USERS`
6. `hermes gateway restart`

**Если бот падает с `longpoll for this group is not enabled`** — включить Long Poll
программно через API (метод включения настроек Long Poll), интерфейс иногда не сохраняет.

**Особенность VK:** чтобы сообщество могло писать пользователю, тот должен разрешить
сообщения. **Если пользователь написал сообществу первым — это уже согласие**, дальше
ограничений по времени нет. События `message_allow` / `message_deny` приходят в Long Poll,
и список разрешивших нужно хранить на своей стороне (через API его не получить).

**Требование:** плагин требует **Hermes ≥ 0.21.3**, у нас сейчас **v0.21.0**
(«23615 commits behind») — перед установкой нужен апдейт.

## Статус внедрения (11.10.2026)

**Сделано:**

- Плагин `web3blind/hermes-vk-platform` v0.2.6 (MIT) установлен и включён:
  `/root/.hermes/plugins/vk-platform/`
- Независимый аудит кода: только stdlib + модули Hermes; нет `subprocess`, `os.system`,
  `eval`, `exec`, `base64`; сеть только к `api.vk.com` и `vk.com`; файлов вне `/tmp` не пишет
- `.env`: `VK_GROUP_TOKEN`, `VK_GROUP_ID=242186684` (сообщество «Hermes vps»), права 600
- VK: Long Poll включён, события `message_new`, `message_reply`, `message_edit`,
  `message_event`, `message_allow`, `message_deny` — все активны
- **Дефолт безопасности плагина:** при пустом allowlist `_is_authorized()` возвращает
  `False` для всех → агент никого не пустит, пока не задан `VK_ALLOWED_USERS`

**Первый барьер (снят):** плагин требует Hermes **≥0.21.3** — конкретно метод
`BasePlatformAdapter._event_session_key`. На 0.21.0 `hermes plugins doctor` давал
`ERROR: Plugin registration failed ... Missing host APIs: BasePlatformAdapter._event_session_key`.

**Апдейт Hermes выполнен 11.10.2026:** v0.21.6 (main @ `ae3598c7cd`). После него доктор
плагина — **OK**. Попутно: 4 наших правленых скилла сохранены, из ядра в плагины вынесены
`openviking` и `homeassistant`, наш патч `telegram-forward-prefix.py` **адаптирован под
новую структуру** (версия 2: текст теперь строится через `expand_link_entities`, сигнатура
`_build_message_event` в одну строку) и применён.

**Осталось:** перезапустить gateway — он работал процессом от 04.10 на старых модулях.
Побочный эффект до рестарта: cron-задачи падают с
`cron external worker exited before ownership acknowledgement` (новая фича restart-safe
воркеров не стыкуется со старым процессом; сами скрипты исправны — проверено запуском
вручную). И нужен VK user id в `VK_ALLOWED_USERS`.

## Вариант 2. MAX — есть плагин, но есть юридический барьер

**Плагин у Романа уже написан:** `/root/.hermes/plugins/max/` — `max-platform` v1.0.0,
репозиторий **`github.com/Rem2222/hermes-max-plugin`** (свой, установлен 14.06.2026).
Умеет webhook (прод) и long-polling (dev), текст, картинки, inline-клавиатуры, typing,
aiohttp без внешнего SDK, `MAX_HOME_CHANNEL` для cron. **Установлен, но `MAX_TOKEN` не
задан** — платформа не активна.

**Барьер (проверено по официальной доке `dev.max.ru/docs/chatbots/bots-create/create`
в браузере):**

> «Подключение к платформе MAX для партнёров и её сервисам — чат-ботам, мини-приложениям,
> каналам — доступно для **юрлиц, ИП и самозанятых**, которые являются резидентами РФ.»

В меню документации — «Создание профиля организации, ИП или самозанятого». Дальше:
верификация профиля (например, через Госуслуги или бизнес-ID банка) и **модерация бота**.
`Masterbot` в официальной документации **отсутствует** — статьи, обещающие «бота за 5 минут
через Masterbot», описывают иную/устаревшую схему.

**Вывод:** физлицу бота в MAX не создать. Путь открыт, если у Романа есть ИП/самозанятость
или если бота заведёт его компания.

**Сертификаты (важный технический нюанс):**

- `botapi.max.ru` — сертификат **HARICA DV TLS RSA** (греческий УЦ) — с нашего VPS работает
- `platform-api2.max.ru` — сертификат **Russian Trusted Sub CA / Russian Trusted Root CA**
  (**Минцифры**). На VPS корневого сертификата нет → TLS-ошибка `unable to get local issuer
  certificate`. Для работы с `platform-api2` нужно добавить корневой сертификат Минцифры
  в системный trust store
- документация MAX прямо просит переходить на `platform-api2.max.ru` и добавить сертификат
  Минцифры в доверенные

**Плагины MAX от сообщества (если барьер снимется):** `RuslanStrogov/max-hermes-plugin`
(5⭐, MIT, свежий), `Realmagnum/hermes-max-integration` (8⭐, MIT, со STT-распознаванием
голосовых), `vladimiraldushin/hermes-max-platform` (10⭐, MIT, но пуш июнь 2026).

## Вариант 3. TrueConf

Механизм есть — **ChatBot Connector API** (см. [[tools/trueconf-bot]]). Ограничения:
нужен TrueConf Server **5.5+** и **админский доступ** к нему, а корпоративный сервер живёт
в домене `.loc` (локальная сеть) и с нашего VPS напрямую не виден.

## Вариант 4. Яндекс.Мессенджер

Bot API существует (`yandex.ru/dev/messenger/doc/ru/`), авторизация по OAuth-токену, но
бот создаётся в **Яндекс 360 для бизнеса** — то есть снова нужна организация.

## Вариант 5. Email (резерв, нулевой код)

У Hermes **уже есть** email-платформа. Если почтовый домен (Яндекс.Почта, Mail.ru) входит
в белый список, канал работает без единой строчки кода: Роман пишет письмо → агент отвечает
письмом. Минус — медленно и неудобно для диалога, но как аварийный канал годится.

## Сравнение

| Канал | Барьер | Готовый плагин Hermes | Двусторонний |
|:---|:---|:---|:---|
| **VK** | нет (сообщество создаёт любой) | да, MIT, свежий | да |
| MAX | юрлицо/ИП/самозанятый + верификация + модерация | **свой, уже установлен** | да |
| TrueConf | админ TrueConf Server 5.5+ | нет (пишется адаптер) | да |
| Яндекс.Мессенджер | Яндекс 360 для бизнеса | нет | да |
| Email | нет (если домен в списке) | **уже в Hermes** | да (медленно) |
