## Что это

Две половины в одном пакете, и путать их не надо.

**Первая — библиотека поведений.** `@ui-sdk/core` — примитивы (фокус, клавиатура, ARIA, управление состоянием), из которых собираются компоненты. Адаптеры: React, Vue, Svelte, Web Components. Идея: поведение отдельно от стиля, поэтому и человек, и агент собирают компонент из готовых кирпичей, не переизобретая доступность.

**Вторая — мост «агент ↔ интерфейс».** Это то, ради чего проект существует. Мост создаётся до рендера страницы:

```js
import { createAgent } from "@ui-sdk/react/agent";
const agent = createAgent();
```

После рендера `agent.snapshot()` отдаёт инвентарь страницы — компоненты, их состояние, доступные действия:

```json
{ "ref": "c1", "component": "input", "label": "Project name",
  "value": "Apollo", "actions": ["setValue", "clear"] }
```

Агент действует по метке, а не по CSS-селектору:

```js
await agent.act({ steps: [{ ref: "Project name", action: "setValue", args: ["Atlas"] }] });
```

Изменение проходит через API самого компонента и его change-callback. Приложение может дать `allow`-callback и отклонить запрос. Change-callback получает `source: "agent"` — то есть интерфейс всегда знает, что нажал не человек, и может отменить. Инструменты моста можно отдать своему агенту или зарегистрировать в браузере через **WebMCP**.

## Бенчмарк (первоисточник, дословно)

Задача: переименовать проект, обновить состав участников и настройки уведомлений, сохранить. Медианы трёх прогонов, Sonnet через Claude Code, одинаковый промпт, все прогоны успешны.

- Вызовов инструментов: 16 → 5 (−69%)
- Прочитано текста: 39.8k → 6.8k символов (−83%)
- Время: 41 с → 16 с (−61%)
- Стоимость: $0.073 → $0.032 (−56%)

Важная оговорка, которой нет в пересказах: сравнивали **браузерные инструменты на странице, собранной другой библиотекой**, против **моста на той же странице, собранной на ui-sdk**. То есть это не только про мост, но и про то, что ui-sdk-страница изначально размечена так, что её состояние читаемо.

## Чем отличается от A2UI

| | A2UI (Google) | UI SDK (Vercel) |
|---|---|---|
| Кто рисует | приложение рисует сцену, присланную агентом | интерфейс уже построен, агент им управляет |
| Направление | агент → интерфейс, «что показать» | агент → интерфейс, «что нажать» |
| Что нужно от приложения | реализовать рендерер каталога компонентов | подключить мост к существующим компонентам |
| Статус | спека 1.0 стабильна, библиотеки 0.x | всё в бете 0.1.0 |

Это два разных ответа на одну проблему. A2UI: «человеку не нужен свой экран, пусть агент его нарисует». UI SDK: «экран у человека свой, но агенту не надо его перечитывать глазами».

## Что это меняет для нас

1. **Главный сдвиг — не в модели, а в интерфейсе.** Все наши истории про «модель подешевле» бьются об одно: агенту дорого читать страницу. Здесь экономия 83% текста достигнута без смены модели — сменился контракт между страницей и агентом.
2. **У нас этот принцип уже работает там, где нужен.** MCP-инструменты SmithsChat — это тот же мост: агент не парсит веб-интерфейс, а вызывает `send`, `history`, `request_approval`. Подтверждения из `payload_json` с проверкой хеша — это `allow`-callback, только снаружи. То есть идею мы применили раньше Vercel, просто в своём домене.
3. **Чего у нас нет, и это стоит взять:** change-callback с пометкой `source: "agent"` и правом отменить изменение внутри самого интерфейса. У нас сейчас отмену делает серверный слой, а не компонент. В tgwidget-карточках вообще нет обратной связи: `editMessageWidgetData` меняет данные, но не сообщает, кто их поменял.
4. **WebMCP — вот что действительно стратегически значимо.** Если браузерный стандарт (Chrome docs, `webmachinelearning/webmcp`) приживётся, страницы начнут публиковать инструменты штатно, и браузерные агенты перестанут парсить DOM повсеместно. Тогда «мост» станет нормой, а не фичей одной библиотеки. Это меняет наши оценки любого браузерного автоматизации-подхода — от Playwright до нашего спа-скрапера.
5. **Как зависимость — не берём.** Бета 0.1.0-beta.2, React 19+/Vue/Svelte/Solid, а наши веб-поверхности — Jinja-шаблоны SmithsChat и Telegram-виджеты. Ставить некуда. Пересматривать, когда появится своё React-приложение.
6. **Экономика в цифрах:** $0.073 против $0.032 за задачу — на 1000 задач разница $41. Это не «вдвое дешевле модель», это вдвое дешевле операция; для агентных сценариев с панелью управления разница накапливается быстро.
