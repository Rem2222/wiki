# RAGFlow

**RAG-движок**, а не «платформа приложений». Весь фокус на том, что происходит **до** поиска: разбор документа.

- Репозиторий: https://github.com/infiniflow/ragflow · сайт: https://ragflow.io
- Лицензия: **Apache-2.0** (настоящий open source, без доп. условий)
- Язык: Go (ядро), Python (парсинг/модели)
- Создан: 12.12.2023 · последний релиз на 19.10.2026: **v1.0.0-rc2** (16.10.2026) — то есть 1.0 ещё RC

## Главная идея: «Quality in, quality out»

Большинство провалов RAG — не провалы поиска, а провалы **парсинга**: таблица превратилась в кашу из слов, двухколоночный текст перемешался. RAGFlow ставит layout-aware разбор в начало пайплайна:

- DeepDoc: распознаёт структуру (таблицы, рисунки, колонки), связывает подписи с объектами
- OCR для сканов
- Несколько стратегий чанкинга: под структуру (таблицы), под смысл (нарратив), смешанная
- **Цитаты/溯源**: показывает, из какого фрагмента (и страницы) взят ответ
- Веб-UI показывает сами чанки — видно, что именно получит модель

## Ресурсы (это главное ограничение)

- Минимум: 4 ядра / **16 ГБ RAM**, рекомендуется 32 ГБ
- Диск: от ~100 ГБ (Elasticsearch + MinIO + Redis + приложение)
- Обязательно поднять `vm.max_map_count` в системе — иначе Elasticsearch не стартует
- Многоконтейнерный стек: Elasticsearch (или Infinity), MinIO, Redis, основной сервис
- Установка: ~полдня, обслуживание — средне-высокое (5 stateful-сервисов)

## Кому

- Много PDF со **таблицами, сканами, сложной вёрсткой** (договоры, отчёты, тех. спецификации) — вот здесь он сильнее AnythingLLM и Dify
- Нужна трассируемость ответа («из какой страницы») — важно для аудита и юристов
- Есть железо (16–32 ГБ) и желание им заниматься

## Наш контекст

VPS: 11 ГБ RAM (свободно ~7), диск 96 ГБ занят на 82% (свободно 18 ГБ). RAGFlow в эти рамки **не влезает**: нужен диск под ES и 16+ ГБ памяти. Если когда-то понадобится глубокая работа с PDF-таблицами — это отдельная машина или домашний ПК (XE2690, 64 ГБ RAM), не наш VPS.
