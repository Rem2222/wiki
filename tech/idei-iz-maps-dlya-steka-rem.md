## 1. «У каждого факта ровно один дом» — в работу

Правило MAPS: факт живёт в **одном** месте, всё остальное только ссылается. Сейчас у Rem фактически **четыре** хранилища, и они уже разошлись — это подтверждено замером ниже.

### Где что лежит сейчас (проверено 2026-09-30)

| Хранилище | Путь | Объём | Статус |
|---|---|---|---|
| **Вики** | `~/Documents/wiki/` | git + LiveSync | основное, zvec-индексировано |
| **Hermes MEMORY.md** | `/root/.hermes/memories/MEMORY.md` | 4 232 байта при лимите **3 300** → переполнен | правила + справочник вперемешку |
| **Hermes USER.md** | `/root/.hermes/memories/USER.md` | 2 945 при лимите **2 000** → переполнен | дублирует OV-профиль |
| **OpenViking** | `/root/.openviking/data/viking/default/user/default/memories/` | **1 710 .md**: facts 1 254, events 185, entities 104, sessions 124, preferences 32, patterns 2 | активно дополняется |
| **AgentMemory (iii)** | docker `agentmemory-iii-engine-1`, том 75M | конфиг `/root/.hermes/node/lib/node_modules/@agentmemory/agentmemory/iii-config.docker.yaml` | up 2 недели |
| **Hindsight** | docker `hindsight-app` / `hindsight-db` | том **1.1G** | **Exited 3 недели назад** — мёртв |
| **zvec** | `/root/.zvec-wiki/index` | производный индекс вики | норма, не хранилище |

Конфиг Hermes: `memory.provider: openviking`, `write_approval: false`, лимиты `memory_char_limit: 3300` / `user_char_limit: 2000`.

### Доказанное дублирование

1. **OV зеркалит wiki.** `entities/software/` = **47 файлов**. Файл `entities/software/bai.md` (создан 30.09 **00:10**) содержит те же base_url, эндпоинты, дилы и цены, что и wiki-страница `tech/bai.md` (обновлена 30.09 **12:26**). Два дома, и они уже разошлись по времени.
2. **Активный канал — события.** В OV `events/`: 178 шт. создано 05.09 (bulk) и **7 шт. сегодня, 30.09** (`bai_evaluated`, `zerotwo_evaluated`, `command_code_evaluated`, `opencode_deepseek_wiki`, `git_pat_status`…) — это ровно содержимое wiki `log.md`, продублированное.
3. **Facts статичны.** Из 1 254 файлов `facts/` — 1 252 созданы 04.09 одним импортом, 2 — 05.09, **роста с тех пор нет**. Аномальный рост «13k+ фактов» был эпохи Hindsight, OV его не наследует.
4. **MEMORY.md и USER.md переполнены** (100% и 95% от лимита) — из-за того, что в них лежит справочник, который должен жить в вике.

### Как устроен канал извлечения (проверено)

Очереди OV: `Embedding`, **`Semantic`**, `ExternalParse`, `AddResource`, **`SessionCommit`**, `UserDeletion` (`queue.db`, обработано 7 044 сообщения). Сервер: `openviking-server --config /root/.openviking/ov.conf`, семантический экстрактор — VLM `mimo-v2.5` через opencode-go (сессия `openviking-semantic-v1`). MCP-мост `/root/scripts/openviking-mcp.py` (111 строк) даёт только `viking_search` / `viking_remember` / `viking_add_resource` — **само извлечение серверное**, через мост его не выключить.

### Целевая схема «один дом»

| Тип факта | **ДОМ** (единственный) | Производные — только ссылки/индекс |
|---|---|---|
| Сервисы, инструменты, порты, версии, цены, API | wiki `tech/*`, `ops/services/*` | zvec-индекс; OV `entities` |
| Правила общения и предпочтения | `USER.md` (короткий) | OV `preferences` |
| Оперативное состояние (идёт rebuild, баланс 0) | `MEMORY.md` | — |
| События («30.09 подключили B.AI») | wiki `log.md` (append-only) | OV `events` |
| Прошлые сессии | `~/.hermes/state.db` — **никогда не чистить** | `session_search`; OV `sessions` |
| Поиск | — | zvec, OV vectordb |

### Что править — конкретно по файлам

1. **`/root/.hermes/memories/MEMORY.md`** — разметить каждую строку: *правило* / *справочник* / *состояние*. Справочное («OpenViking v0.4.17.1 :8900», «Docker log rotation 50m×3», «qwen-tp endpoint») → перенести в wiki-страницы, в MEMORY.md оставить **одну строку-указатель** `→ wiki/ops/services/openviking.md`. Цель: ≤50% лимита.
2. **`/root/.hermes/memories/USER.md`** — снять дубли с OV `profile.md` / `preferences/*`. В USER.md оставить только то, что обязано работать **при недоступном OV**: имя, язык, канал, жёсткие правила (без мата, plan-first, interrupt).
3. **OV `entities/software/*` (47 файлов)** — свести к ссылкам на wiki или отключить автосоздание. Переключатель искать в серверной политике очереди `Semantic` (`ov.conf` + настройки сервера); MCP-мост тут ни при чём. **Точный ключ уточню при внедрении, сейчас не выдумываю.**
4. **OV `events/*`** — событие пишется строкой в wiki `log.md`, в OV — только ссылка. Сегодняшние 7 файлов дедупить.
5. **Дисциплина `viking_remember`** — вызывать только для факта, которого **ещё нет** в вике, и сразу с решением «куда это пойдёт». Зеркалить wiki в OV — перестать.
6. **`write_approval: false` → `true`** — у Rem правило «MEMORY.md наполнять только по согласованию», а сейчас инструмент пишет без спроса.
7. **Hindsight** — контейнеры Exited 3 недели, том **1.1G**. Рядом с темой «один дом»: спросить, удалять ли (это чистка, не перенос).

### Порядок работ (после «угу»)

1. Аудит MEMORY.md / USER.md: разметка строк по трём категориям — я
2. Перенос справочника в wiki + указатели в MEMORY.md
3. Чистка USER.md против OV-профиля
4. Найти ключ серверной очереди `Semantic` в OV и отключить автосоздание entities/events для того, что уже в вике
5. Дедуп 47 entities + 7 events против wiki
6. Повторный прогон: `zvec-wiki "<тема>"` и `viking_search` должны вести **на один и тот же дом**

**Цена:** ноль рублей, несколько часов. **Эффект:** перестаёт спорить, где правда.

## 2. Rolling-пробки на cron-рутинах — на будущее

**Статус: пока не актуально** (вердикт Rem 2026-09-30). Оставляется как план на случай, когда расход на рутинах начнёт ощущаться.

Суть MAPS: лимит на рутине — **две штуки**, обе читаются из одного лога прогонов: дневной потолок + короткое rolling-окно (5 часов / неделя). Каждая рутина пишет строку `время | job_id | модель | ходы | стоимость | статус`.

Что есть у Rem: `/gquota` (видимость по Gemini), 3-минутный hard-interrupt на прогон Hermes cron. Чего нет: единого потолка по расходу и rolling-окна.

Чем это грозит, когда станет актуально: interrupt убивает **конкретный прогон**, но не мешает джобе стрелять каждые N минут весь день. Прецедент — спам из `check-*.sh` → скилл `cron-job-forensics`.

Тогда сделать: (1) строка в `~/.hermes/logs/cron-runs.log` на каждый прогон, (2) `cron-caps.sh` — суточный потолок + rolling-окно, (3) превышение → `hermes cron pause <id>` + ntfy, (4) пороги согласовать.

## 3. `brain.json` — отклонена

**Статус: мимо.** Причина: **Obsidian graph view уже закрывает** эту потребность — граф wikilinks есть в редакторе, отдельный слой с дашбордом не нужен. Всё остальное в этой карточке (нightly обход, шесть видов, d3) становится ненужной работой.
