# Herdr

Терминальный **рантайм и мультиплексор для AI-кодинг-агентов**, написанный на Rust. Идея: tmux, переосмысленный под агентов — те же панели и префиксные клавиши, но с состояниями «работает / заблокирован / простаивает», отсоединением без остановки работы и управлением агентами через CLI и socket API.

Девиз проекта: *the runtime your coding agents live on*.

Установка:

```bash
curl -fsSL https://herdr.dev/install.sh | sh
```

или `brew install herdr`, `mise use -g herdr`; на Windows — через PowerShell-установщик. Запуск: `herdr`, отсоединение `ctrl+b q`, вернуться — снова `herdr`.

## Возможности (по README)

- **Отсоединение без остановки работы** — терминалы держит фоновый сервер, поэтому закрытие клиента или обрыв SSH не убивает работу. После перезапуска сервера или машины herdr восстанавливает сохранённую раскладку и может продолжить поддерживаемые сессии агентов; исходные процессы, разумеется, не выживают
- **Несколько машин в одном окне** — локальная работа и сохранённые SSH-машины вместе, общий список агентов, независимые переподключения
- **Понятные состояния панелей** — работаю / заблокирован / простаиваю; когда агент встал и ждёт ответа, herdr это показывает, искать «зависшего» вручную не нужно
- **Агент-нативность** — агенты управляют herdr через CLI и socket API: создают панели, отправляют промпты друг другу, ждут, пока другой агент реально заблокируется. Для агентов есть готовый skill-файл
- **Запускает существующих агентов** — Claude Code, Codex, Cursor, opencode, grok и прочие; herdr их не оборачивает и не заменяет, а владеет их терминалами
- **Клавиатура и мышь равноправны** — префиксные клавиши в стиле tmux и одновременно клики, drag, split; выбираешь под момент, а не под инструмент
- **Плагины** — расширение панелей и сценариев работы, есть маркетплейс
- **Интеграции**: local socket API (ответы в JSON) и CLI-справочник — через них herdr можно автоматизировать снаружи

## Поддержка агентов: любые, но с разной глубиной

Дословно из документации: *«Other agents still run normally in Herdr panes. They just show up as plain terminals»* — запустить можно любого, любой терминальный процесс. Разница в том, видит ли herdr состояние агента (`idle` / `working` / `blocked`) и умеет ли сказать, что агент встал и ждёт ответа.

**Herdr распознаёт сам** (читает живой низ панели, а не то место, куда ты прокрутил): Claude Code (`claude`), Codex (`codex`), GitHub Copilot CLI (`copilot`), Cursor Agent CLI (`cursor`), OpenCode (`opencode`), Pi (`pi`), OMP (`omp`), Droid (`droid`), Devin CLI (`devin`), Kimi Code CLI (`kimi`), Kilo Code CLI (`kilo`), **Hermes Agent (`hermes`)**, Qoder CLI (`qodercli`), Qwen Code (`qwen`), Letta Code (`letta`), MastraCode (`mastracode`), Grok CLI (`grok`), Antigravity CLI (`antigravity-cli`). Только состояние, без интеграции: Amp, Kiro CLI, Maki, Gemini CLI (менее обкатан), Cline (менее обкатан).

**Агент репортит себя сам** (ничего устанавливать не нужно, просто запустить в панели): Command Code, Crush, Kiro CLI, Muse Code, Prime Agent. Если агент сообщает ещё и команду resume — после перезапуска сервера herdr вернёт его в ту же сессию.

**DeepSeek Harness (DSH) в списках отсутствует** — проверено 2026-10-28. Варианты: запускать как обычный терминал (без состоянии и уведомлений) либо добавить поддержку самому — `herdr.dev/tui/docs/add-herdr-support/`, по словам авторов это несколько вызовов.

**Hermes Agent — в списке поддерживаемых**, с интеграцией `hermes`: herdr видит его состояние и поднимает сессию после перезапуска. Практический вывод: сценарий «сначала поставить opencode и пасти его» — не единственный, можно сразу ставить herdr и запускать в панелях самого Hermes.

## Чем отличается от tmux и от Hermes

**От tmux** — состояниями агентов и API: tmux знает про панели, но не знает, что внутри сидит агент и что он «заблокирован и ждёт ввода». Herdr это знает и умеет будить по этому событию другого агента. Плюс восстановление раскладки после перезапуска и продолжение поддерживаемых сессий.

**От Hermes** — уровнем: Hermes это серверный агент (фоновые задачи, Telegram, расписания, память между сессиями), а Herdr — рантайм для **интерактивных CLI-агентов** (Claude Code, Codex, opencode). Они не конкурируют: herdr владеет терминалами, Hermes владеет задачами.

## Применимость у нас

Состояние на 2026-10-28 (проверено на VPS): `claude`, `codex`, `cursor`, `opencode`, `grok` — **ни одного не установлено**, `herdr` тоже нет, из терминальных инструментов есть только `tmux`.

То есть из CLI-агентов пасти пока некого. Но **Hermes Agent в списке поддерживаемых есть**, поэтому первый практический сценарий проще, чем казалось: поставить herdr и запускать в панелях самого Hermes — состояние, уведомления о блокировке и восстановление сессии работают из коробки, ничего дополнительно устанавливать не нужно. Расширенный сценарий — привести и внешних агентов:

1. Поставить CLI-агента — первый кандидат **opencode** (конфиг на машине уже есть, бинарника нет).
2. Поставить herdr и запускать агентов в панелях, работая по SSH.
3. Научить Hermes пользоваться socket API и skill-файлом herdr: запускать CLI-агентов, ждать их блокировки, передавать работу между ними.

Третий пункт — это то же направление, что в заметке про [[tech/gvs5h-pyat-instansov-odnoy-modeli-vmesto-bolshoy-metod-i-nezavisimoe-vosproizvedenie]]: несколько агентов координируются между собой, только здесь координация идёт через терминалы и файлы состояния, а не через журнал.

Ограничение по ресурсам: сам herdr — один Rust-бинарник, накладные расходы минимальны; тяжесть создают агенты внутри панелей (каждый — свой процесс и своя модель).
