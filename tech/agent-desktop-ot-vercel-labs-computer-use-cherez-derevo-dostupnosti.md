# Agent Desktop от Vercel Labs — computer use через дерево доступности

## Что это

`vercel-labs/agent-desktop` — CLI и C-библиотека для computer use: агент читает и управляет приложениями рабочего стола через **дерево доступности операционной системы**, без анализа пикселей. Лицензия Apache-2.0, написан на Rust, ставится одной командой `npm install -g agent-desktop`; есть готовые нативные сборки под x86_64 и ARM64 для macOS, Windows и Linux.

## Как устроен цикл работы

Схема в три шага, без пиксельного матчинга:

1. `agent-desktop snapshot --app Finder -i` — возвращает JSON, где у каждого доступного элемента есть `ref` вида `@s8f3k2p9:e8`
2. `agent-desktop click @s8f3k2p9:e8` — действие по этому ref
3. снова `snapshot` — проверка результата

Ключевая деталь надёжности: **refs принадлежат своему снимку**. Голый `@e8` отвергается с `INVALID_ARGS`, устаревший ref даёт `STALE_REF`, неоднозначная цель — `AMBIGUOUS_TARGET`. Отсюда правило «действия безопасно повторять»: повтор после сбоя не попадёт в другой элемент с тем же идентификатором.

Каждая команда печатает один JSON-конверт с `ok` и либо `data`, либо `error`; у ошибки есть код, `disposition` и обычно подсказка. Повторять разрешено, только когда `error.disposition.retry` равно `safe`.

## Команды и возможности

- **Наблюдение:** `snapshot`, `find`, `get`, `is`, `screenshot`, `list-surfaces`
- **Действия по ref:** `click`, `double-click`, `type`, `set-value`, `clear`, `focus`, `select`, `toggle`, `check`, `expand`, `scroll-to` и другие
- **Плотные приложения:** сначала карта `snapshot --skeleton --app Slack -i --compact`, потом углубление в один регион `snapshot --root @ref -i --compact`
- **Surfaces** — отдельно наблюдаемые слои интерфейса: открытое меню, поповер, алерт, лист
- **Сессии:** `session`, `trace`, **`cursor-overlay`** — это и есть оверлеи курсоров для нескольких агентов сразу
- Всего 60 имён команд, из них 56 рабочих; четыре (`key-down`, `key-up`, `mouse-down`, `mouse-up`) отказываются запускаться, пока демон не умеет отпускать зажатую клавишу

По умолчанию работа идёт **headless**: действия проходят через accessibility API, не двигая указатель и не забирая фокус у пользователя. Флаг `--headed` включает физический ввод.

## Права доступа по платформам

- **macOS** — требуется разрешение Accessibility (`agent-desktop permissions --guide`)
- **Windows** — грантов не нужно для приложений на уровне целостности терминала
- **Linux** — нужна графическая сессия пользователя и `at-spi2-core`

Внутри бинарника лежат готовые инструкции для агентов: `agent-desktop skills get desktop` и `agent-desktop skills get platform`. Отдельного MCP-сервера в репозитории нет — интеграция идёт через CLI, topic `mcp` про подключение такой команды из MCP-клиентов.

## Утверждения из поста против реальности

| Утверждение из поста | Что на самом деле |
|---|---|
| «не нужны скриншоты» | Верно для основного цикла: наблюдение идёт по дереву доступности. Но команда `screenshot` и визуальные артефакты отладки в проекте есть — они опциональны, для человека |
| «работает в фоне и не перехватывает управление мышью» | Верно по умолчанию (headless). Физический ввод и фокус включаются флагом `--headed` |
| «несколько агентов, у каждого свой курсор» | Подтверждается видео и командой `cursor-overlay`; отдельного раздела про мультиагентность в README нет |
| «переносит подход agent-browser на всю ОС» | По сути да: та же идея «снимок структуры → действие по ссылке», но источник — системное дерево доступности, а не DOM |

## Применимость к нашему стеку

**VPS (80.241.218.110) — не подходит.** Графической сессии нет: `DISPLAY` и `WAYLAND_DISPLAY` пустые. Формально есть `Xvfb`, `libatspi.so.0` и node/npm, то есть виртуальный десктоп поднять можно, но приложений в нём нет, а для веба у нас Playwright, который для этой задачи лучше.

**Рабочий ПК на Windows — подходит.** Грантов не требует, ставится одной командой, агент работает в фоне, пока пользователь за компьютером. Это ровно тот сценарий, ради которого инструмент сделан.

**Пересечение с нашим инструментом.** В Hermes уже есть `computer_use` на cua-driver: режим `ax` — только дерево доступности без картинки, режим `som` — снимок с нумерованными метками плюс AX-дерево, ввод по умолчанию background без перехвата курсора, macOS/Windows/Linux. То есть «без скриншотов и не мешая пользователю» у нас уже есть. Что у agent-desktop сильнее: отдельный CLI на Rust с жёсткими гарантиями по ref и retry-семантикой, дренаж плотных приложений по скелетону, оверлеи курсоров для нескольких агентов и вшитые в бинарник инструкции под версию.

**Приватность.** README прямо предупреждает: снимки, чтение буфера обмена, вывод команд и отладочные артефакты содержат содержимое рабочего стола. Их нельзя складывать в публичные логи и загружать наружу. Для нас это значит — не гонять такие снимки в облачные модели без необходимости.

## Установлено на Windows-ПК (01.11.2026)

Клешня (`roma.openclaw`) поставил инструмент на домашний Windows-ПК Романа — установка была согласована с Романом лично, выполнена после его явного «да». Отчёт от 01.11.2026:

- **Версия 1.0.2**, `agent-desktop version` → `{"version":"2.5","ok":true,"data":{"os":"windows","target":"x86_64","version":"1.0.2"}}`
- Ставил через `npm install -g agent-desktop`, глобальный префикс `C:\Users\rem\AppData\Roaming\npm`. **Именно в Windows, а не в WSL** — из WSL процесс не увидел бы приложения рабочего стола
- `list-apps` в foreground показал **20 приложений**: Telegram, Totalcmd, TrueConf, thunderbird, mRemoteNG, explorer, notepad, cmd, wsl, wireguard, hidemy.name VPN, PhoneExperienceHost, Taskmgr, tspc, browser, YandexDiskScreenshotEditor (3 инстанса)
- Пробный `agent-desktop snapshot --app notepad.exe -i` → `ok: true`, `complete: true`, `ref_count: 16`. Дерево прочиталось: текстовое поле документа (role textfield), строка меню (Файл, Правка, Формат, Вид, Справка), кнопки окна, вертикальная полоса прокрутки. Ref-формат как в документации: `@<snapshot_id>:eN`
- Работал headless, без `--headed`, только чтение
- Содержимое снапшотов не передавалось — только метаданные (роли, количество, структура), потому что снапшоты содержат данные рабочего стола

**Осталось непроверенным:** физический ввод (`--headed`) и работа на нескольких приложениях подряд. На VPS инструмент не ставится — там нет графической сессии.

**Статус: установлено на Windows-ПК, проверено живым snapshot. На VPS не ставится.** Решение об установке — за Романом; на VPS ставить не имеет смысла, кандидат — рабочий ПК.
