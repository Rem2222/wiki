# 4 компактные локальные LLM — разбор подборки Компьютерры

Прислана ссылкой `share.google/ZeylypHcHgaPU1CUP`, которая ведёт на `computerra.ru/375391/...`; редирект проверен через поиск, сама короткая ссылка с VPS отвечала таймаутом. Подборка: Qwen3.8-9B-Distill, Ornith-1.5-9B, Qwythos-9B-v2, Llama-3.2-3B-Instruct. Все четыре существуют на Hugging Face — проверено по API 17.11.2026.

## Модели в цифрах

Загрузки GGUF — счётчики каналных репозиториев на 17.11.2026, не базовых: по ним видно, чем реально пользуются. У Ornith цифра особенно высокая — 5,7 млн, так что это не хайп вокруг звёзд.

**Qwen3.8-9B-Distill.** Полная дистилляция Qwen3.8 2.4T A95B в архитектуру Qwen3.5-9B, ~70 000 траекторий учителя, SFT. В карточке заявлены те же цифры, что и в статье: GSM8K flexible 0,885 → 0,870 (−1,5 п.п.), MMLU flexible 0,546 → 0,751 (+20,5 п.п.). Нативный function calling, `<think>`-рассуждение, 262K контекста. Зрение — через отдельный файл `mmproj`, базовый репозиторий описан как текстовая ветка vision-language модели. Язык в карточке: `en`.

**Ornith-1.5-9B.** 9B dense из семейства 397B / 35B / 9B. Петля самоулучшения: модель сама генерирует задачи, строит scaffold и делает rollout для RL. В блоге авторов — Terminal-Bench 2.1 ≈47 и SWE-Bench Verified 70,6; в таблице карточки Terminal-Bench 2.1 = 46,2. Есть квантованный mobile-вариант под телефоны. В карточке язык не указан; в статье разработчик назван «DeepReinforce», но на HF репозиторий называется `ornith-ai` — несовпадение, которое статья не объясняет.

**Qwythos-9B-v2.** Намеренно нецензурированная модель на базе Qwen3.5-9B, 1M контекст, MTP-голова восстановлена. Главное изменение v2 — зацикливание при greedy-декодировании снижено с 6,7% до 0% методом FTPO. Замеры авторов (внутренний харнесс): MMLU 83,8, GSM8K 93,6, HumanEval 77,4. Замер скорости в статье — **≈30 токен/с на RTX 3060 8 ГБ при контексте ~68K и KV-кэше Q5_1**; это конкретный стенд автора, не системный эффект. Язык в карточке: `en`.

**Llama-3.2-3B-Instruct.** 3,21 млрд параметров, 128K контекста, gated-доступ, лицензия llama3.2. В статье есть сноска про признание Meta экстремистской организацией и запрет в РФ — юридический риск, а не техническое качество. Официальные языки Llama 3.2: английский, немецкий, французский, итальянский, португальский, хинди, испанский, тайский; **русского в списке нет** (карточка говорит об обучении на большем числе языков, но гарантии качества нет).

## Утверждение из статьи → проверка

| Утверждение | Что подтвердилось |
| --- | --- |
| «−1,5 п.п. GSM8K, +20 п.п. MMLU у дистилляции» | Цифры из карточки модели совпадают. Но это замер авторов через `lm-evaluation-harness`, а не независимый бенч. |
| « function calling, рассуждение, зрение через mmproj» | Function calling и CoT подтверждены карточкой; vision — как отдельный `mmproj`, в текстовом репозитории не встроен. |
| «Ornith от DeepReinforce» | На HF — `ornith-ai`, в блоге — Ornith. Приписывание DeepReinforce карточкой не подтверждено. |
| «RL-петля сама планирует и проверяет решение» | Подтверждено блогом и карточкой; авторы же предупреждают о повышенном расходе токенов и контекста. |
| «≈30 tok/s на RTX 3060» | Замер автора на своём стенде, не гарантия для другого железа. У нас RTX 3060 нет. |
| «Llama 3.2 многоязычна» | Да, но официально 8 языков и без русского. Для наших текстов нужен живой прогон. |
| «Q4_K_M + Q8_0 для KV-кэша экономят память» | Q4_K_M — разумный старт. Q8_0 экономит относительно fp16, но **не** относительно Q5_1, который автор применил для 68K; формулировка статьи неоднозначна. |
| «MTP, 3 черновых токена — проверить, а не предполагать» | Согласно: MTP-голова подтверждена у Qwythos, но ускорение надо мерить на конкретном рантайме. |

## Как запускать по статье

- Начать с сборки **Q4_K_M**, где она есть.
- Для длинного контекста — квантовать K/V-кэш; сравнение делать с родным для рантайма режимом, а не вслепую ставить Q8_0.
- Где поддерживается MTP — прогнать 3 черновых токена и сравнить с выключенным.
- Для vision у Qwen-дистилляции докачать `mmproj`.
- Одна модель за раз, замер на своём железе, потом подкрутка.

## Чем интересно Роману

Проверено живо 17.11.2026: `ollama` в PATH, локально только `qwen2.5:7b` (4,7 ГБ) и `bge-m3` (1,2 ГБ); `llama-server`/`llama-cli` в PATH нет. RAM 11 ГБ (доступно ~8 ГБ), диск `/` на 93% — **свободно 6,9 ГБ**. GPU на VPS нет; домашняя машина — 64 ГБ RAM и GT 1030 на 2 ГБ.

- **Сейчас:** Ollama крутит `qwen2.5:7b` как местную модель → **стало бы:** Qwen3.8-9B-Distill Q4_K_M (~5–6 ГБ) как более свежая замена с function calling. Но сначала надо освободить диск: 6,9 ГБ свободно — впритык.
- **Сейчас:** агентный код через облачного провайдера → **стало бы:** Ornith-1.5-9B внутри OpenCode; авторы обещают лендинги и мелкие CLI за один проход, но RL-петля интенсивно ест контекст — только небольшие задачи.
- **Сейчас:** RAG по вике на `bge-m3` + локальная модель → **стало бы:** Llama-3.2-3B Q4 на мини-ПК без дискретной видеокарты; русский не заявлен, поэтому нужен прогон на наших текстах (объявления, 1С, переписка).
- **Сейчас:** творческие тексты в облаке → **стало бы:** Qwythos-9B-v2, но это осознанно нецензурированная модель — не для клиентских и рабочих переписок.

**Чего НЕ делает:** не гарантирует качество на русском (у трёх моделей в карточке `en`, у Llama русского нет в официальном списке); не превращает GT 1030 2 ГБ в 3060; не снимает юридический вопрос вокруг Meta; не ускоряет голосовой путь — туда локальные LLM по-прежнему не ставятся; не заменяет проверку на живом прогоне чужие цифры tok/s.
