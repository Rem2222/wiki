# 1С: автономная разработка с ИИ-агентами — паттерн двух проектов

«Классический» уже паттерн для задач вроде: перенос изменений и доработки одной конфигурации на основании другой, разработка интеграций между ними (для этого, кстати, отлично заходит MCP-конвертация), обновление через «100500 релизов» и прочее.

## 1. Разворачиваем два проекта для разработки с ИИ

- Два проекта (источник → приёмник / обе базы) с правилами.
- Harness для них должен быть вменяемым — любой современный поддерживает **ACP**, CLI обязателен для поддержки ACP.

## 2. Проверяем настройки проектов

- MCP подключены, индексы проиндексированы и т.п.
- Не забываем установить CLI, если его нет (например, Cursor CLI ставится отдельно).

## 3. Разворачиваем автономного агента

- Hermes или OpenClaw.
- **Графовый MCP** и **MCP для работы с данными** подключаем обязательно, остальные — по желанию.
- Автономному агенту «объясняем», где находятся базы и проекты для них, где публикации — и просим их исследовать.

## 4. Запускаем автономно через `/goal`

- Ключом `/goal` даём автономному агенту команду написать **спецификации** для разработки в базе-приёмнике (или в обеих) — используя Cursor / Claude Code / Codex и нужную модель.
- Спеки лучше прочитать, но это зависит от цены и критичности изменений.

## 5. Выполняем разработку

- Снова через `/goal` даём команду **выполнить разработку** (Cursor / Claude Code / Codex + модель).
- Просим мониторить сессии и отчитываться о прогрессе каждые N минут/часов, исправлять блокеры.
- Наблюдаем за прогрессом в Telegram.

## Что получаем

- ✅ Long-running задача почти любого размера — автономный агент держит хорошо, даже при рестартах.
- ✅ Агент создаёт себе skill (или область в памяти) и улучшает по мере выполнения и устранения блокеров — люто экономит время и токены; повторный запуск становится проще.
- ✅ Работу агента можно скорректировать через чат в Telegram по его отчётам.
- ✅ Разработку ведут специализированные агенты для разработки — с настроенным инструментарием, MCP и правилами под workflow разработки (а не общий профиль, разбавленный памятью и инструкциями по автономности).
- ✅ Если агент разработки валится или не может что-то — его корректирует автономный агент. Сложные и массовые операции выполняет агент разработки, так что именно у него больше шансов свалиться.
- ✅ При возможности параллелить — автономного агента можно попросить делать это.

## Связь с кластером серверов 1С

Ничто из этого не напоминает? Как минимум кластер серверов 1С следует примерно тем же принципам.

## Модели

- Для автономного агента в таких задачах — что-то приличное, **с reasoning**.
- Для спецификаций по традиции — самое крутое, что можно себе позволить.
- Для разработки — то, что обычно используете, в зависимости от вендора.
- Примеры: Grok / Terra / Opus (для тех, кто может себе позволить).
